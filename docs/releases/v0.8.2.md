# v0.8.2 — File Read Tools

## Mục tiêu

Mở rộng Tool Framework bằng khả năng đọc file local theo mô hình workspace được cấp quyền, nhưng chưa cho AI ghi, sửa hoặc xóa file.

## Công cụ mới

### `workspace.list`

- Liệt kê trực tiếp file/thư mục trong một đường dẫn tương đối của workspace.
- Không duyệt đệ quy tự động.
- Tối đa 200 entry mỗi lần gọi.
- Chỉ trả đường dẫn tương đối, không trả absolute path của máy.
- Symbolic link / reparse point không được đi qua; entry dạng link bị bỏ khỏi listing và được đếm trong `blockedSymlinks`.

### `workspace.read_text`

- Đọc file văn bản UTF-8 bên trong workspace.
- Chỉ nhận đường dẫn tương đối.
- Chặn `..`, absolute path, path thoát khỏi workspace và traversal qua symbolic link / reparse point.
- Giới hạn file 512 KB.
- Giới hạn nội dung trả về tối đa 200.000 ký tự; mặc định 100.000 ký tự.
- Nếu nội dung bị cắt, response trả `truncated=true`, `characterCount` và `returnedCharacterCount`.
- Từ chối dữ liệu UTF-8 không hợp lệ hoặc file có dấu hiệu nhị phân.

## Workspace root

Workspace root được lấy theo thứ tự:

1. Cấu hình `Workspace:Root` nếu có. Với environment variable của .NET có thể dùng `Workspace__Root`.
2. Nếu chưa cấu hình, ứng dụng dùng workspace local mặc định tại `PersonalAI/Workspace` trong Local Application Data của hệ điều hành và tự tạo thư mục này.

Khi cấu hình một workspace root riêng, ứng dụng không tự tạo đường dẫn đó; file tool sẽ báo lỗi nếu thư mục chưa tồn tại.

## Permission và an toàn

- Cả hai tool mới chỉ yêu cầu `READ`.
- Không có write, delete, shell, HTTP, browser hoặc connector access trong v0.8.2.
- Tool chỉ hoạt động trong workspace boundary; không thể dùng đường dẫn tuyệt đối hoặc `..` để đọc file ngoài phạm vi.
- Child symlink/reparse point bị chặn để tránh bypass sandbox.
- Tool output vẫn đi qua Tool Execution Service, schema validation, permission policy, timeout và chuẩn hóa JSON camelCase.
- Chat/model vẫn chưa tự động quyết định gọi tool ở bản này.
