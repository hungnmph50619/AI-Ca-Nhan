# PersonalAI v0.8.5 — Tool Calling Orchestration

## Mục tiêu

v0.8.5 nối chat với Tool Framework theo mô hình hai bước: AI chỉ được **đề xuất** một tool call có cấu trúc trước; thực thi là một bước riêng do người dùng chủ động bấm chạy. WRITE/DELETE vẫn phải xác nhận rõ ràng.

## Luồng mới

1. Người dùng bật **Đề xuất công cụ** trong composer.
2. Chat gửi hội thoại đến bộ lập kế hoạch tool.
3. Model chỉ được trả một quyết định JSON: không cần tool, hoặc một tool trong registry cùng arguments.
4. Server không tin trực tiếp output của model. Tool name phải tồn tại trong registry và arguments phải vượt qua input-schema validation.
5. Server tự lấy permission từ registry; model không được tự cấp permission.
6. Proposal được gán ID ngẫu nhiên, hết hạn sau 10 phút và chỉ dùng được một lần.
7. UI hiển thị tool name, lý do, permissions và arguments trước khi người dùng bấm chạy.
8. READ tool có thể chạy bằng thao tác bấm của người dùng; WRITE/DELETE vẫn yêu cầu xác nhận rõ ràng.
9. Lệnh thực thi chỉ nhận proposal ID + trạng thái xác nhận; client không được thay arguments hay permission ở bước thực thi.

## API orchestration

- `POST /api/tools/orchestrate/prepare`: nhận một structured proposal và chuẩn hóa/validate nó theo registry. Endpoint này cũng là primitive dùng để kiểm thử và mở đường cho provider-native tool calling sau này.
- `POST /api/tools/orchestrate/execute`: thực thi đúng proposal đã lưu; không nhận lại tool name, arguments hay permission từ client.

## Chat integration

`ChatRequest` có thêm `useTools` mặc định `false`. Khi bật và đang ở chế độ chat thường, PersonalAI gọi planner trước câu trả lời thông thường. Nếu planner tạo được proposal hợp lệ, chat trả proposal cho UI và **không tự chạy**.

Nếu planner trả `none` hoặc đề xuất không vượt qua server validation, luồng chat thông thường tiếp tục. Chế độ documents-only không bị orchestration chen vào.

## Guardrails

- Opt-in, mặc định tắt.
- Model chỉ thấy catalog tool, description, required permissions và input schema.
- Hội thoại được đánh dấu là dữ liệu không đáng tin cậy trong planner prompt.
- Unknown tool, arguments sai schema hoặc malformed model output không được biến thành executable proposal.
- Permission luôn lấy lại từ registry ở server.
- WRITE / DELETE / EXTERNAL / SENSITIVE tiếp tục chịu policy xác nhận hiện có.
- Proposal hết hạn sau 10 phút.
- Proposal được consume trước khi thực thi để tránh replay/double execution; proposal cần confirmation nhưng chưa xác nhận vẫn được giữ để người dùng có thể xác nhận sau.
- Tối đa 100 proposal đang sống; proposal cũ/hết hạn được dọn tự động.
- Không có autonomous loop, recursive tool calling hay silent execution.

## UI

Composer có toggle **Đề xuất công cụ**. Proposal card hiển thị:

- tool name;
- lý do;
- permission;
- arguments JSON;
- cảnh báo confirmation khi cần;
- nút chạy / xác nhận & chạy.

Kết quả tool được thêm vào hội thoại dưới dạng kết quả có cấu trúc và được giới hạn phần hiển thị để tránh làm phình lịch sử local quá mức.

## Kiểm thử

CI bao phủ:

- version / catalog regression;
- structured proposal với unknown tool;
- schema validation ở bước prepare;
- READ proposal chạy không cần confirmation;
- one-time proposal/replay rejection;
- WRITE proposal bị chặn khi chưa xác nhận;
- WRITE proposal chạy sau xác nhận;
- DELETE proposal bị chặn khi chưa xác nhận rồi chạy sau xác nhận;
- toàn bộ Memory/RAG/internal tools/file mutation regression;
- JavaScript syntax cho app và Tool UI.

## Ngoài phạm vi

v0.8.5 chưa có provider-native function calling, tự động chạy READ tool, tool-result synthesis bằng model, multi-step tool loop, shell, browser hay external connector actions.
