# PersonalAI v0.8.6 — Tool Result Synthesis

## Mục tiêu

v0.8.6 làm cho kết quả tool dễ đọc hơn mà không làm mất nguyên tắc local-first. Sau khi tool chạy, PersonalAI tạo một tóm tắt deterministic ngay trên máy. Nếu người dùng muốn AI diễn giải thêm, đó là một bước riêng có xác nhận rõ ràng vì output tool sẽ được gửi tới nhà cung cấp AI đang cấu hình.

## Luồng kết quả mới

1. Proposal vẫn được tạo và xác nhận theo v0.8.5.
2. Tool chạy qua permission policy hiện có.
3. Server tạo `localSummary` từ output ngay trên máy, không gọi provider.
4. UI hiển thị tóm tắt local và một phần output JSON đã rút gọn.
5. Nếu kết quả đủ điều kiện, người dùng có thể bấm **Diễn giải bằng AI**.
6. Trước khi gửi output ra provider, UI hiển thị xác nhận riêng về việc dữ liệu sẽ rời ứng dụng local.
7. Endpoint synthesis chỉ chấp nhận `invocationId`; client không gửi lại hoặc sửa output tool.
8. Server lấy output gốc đã lưu tạm trong bộ nhớ, giới hạn phần gửi sang AI và đóng gói nó như dữ liệu không đáng tin cậy.
9. Kết quả AI synthesis được cache cho invocation đó để tránh gửi lặp lại cùng output.

## Tóm tắt local

`ToolResultSynthesisService` có deterministic summary cho các tool hiện tại:

- calculator;
- clock;
- text statistics;
- date math;
- memory search;
- document search;
- app summary;
- workspace list/read/write;
- create directory;
- move;
- delete.

Nếu tool mới chưa có formatter chuyên biệt, fallback chỉ xác nhận rằng tool đã chạy thành công, không tự suy diễn output.

## Privacy và prompt-injection guard

- Tool output **không tự động** được gửi tới Gemini/OpenAI.
- AI synthesis cần `confirmedExternal=true` ở một request riêng.
- Tool có permission `SENSITIVE` bị chặn khỏi AI synthesis.
- Output gửi sang AI bị giới hạn 16.000 ký tự.
- Prompt synthesis xác định rõ tool output là dữ liệu không đáng tin cậy, không phải instruction.
- Không gửi lại arguments đầy đủ của tool sang provider; chỉ gửi tool name, proposal reason, local summary và output cần diễn giải.
- AI synthesis bị giới hạn phần trả lời và không được tuyên bố thêm side effect ngoài dữ liệu tool.
- Completed invocation chỉ được giữ tạm trong bộ nhớ khoảng 10 phút, tối đa 100 mục.

## API

### Execution response

`POST /api/tools/orchestrate/execute` trả thêm:

- `localSummary`;
- `canAiSynthesize`;
- `synthesisExpiresAt`.

### AI synthesis

`POST /api/tools/orchestrate/synthesize`

Input:

```json
{
  "invocationId": "...",
  "confirmedExternal": true
}
```

Nếu chưa xác nhận việc gửi kết quả ra provider, API trả 403 trước khi gọi provider.

## UI

Tool result card hiển thị:

- tên tool;
- trạng thái thực thi;
- nhắc rằng tóm tắt hiện tại là local;
- output JSON rút gọn trong phần mở rộng;
- nút **Diễn giải bằng AI** khi còn thời hạn.

Khi bấm diễn giải, người dùng phải xác nhận rằng output sẽ được gửi tới provider đang cấu hình. Kết quả AI sau đó được thêm như một tin nhắn riêng trong hội thoại.

## Kiểm thử

CI bao phủ:

- version/framework regression;
- local summary của calculator;
- completed invocation có thời hạn synthesis;
- synthesis không có xác nhận external bị từ chối 403;
- invocation không tồn tại trả 404;
- local summary của WRITE và DELETE;
- toàn bộ orchestration, permission, Memory/RAG, workspace mutation regression;
- JavaScript syntax.

## Ngoài phạm vi

v0.8.6 chưa dùng provider-native function calling, chưa tự động chạy READ tool, chưa có multi-step agent loop và chưa cho model tự quyết định gửi tool output ra provider. Provider-native tool calling có thể được xây ở phiên bản tiếp theo trên cùng proposal/permission pipeline này.
