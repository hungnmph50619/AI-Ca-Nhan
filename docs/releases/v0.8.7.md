# PersonalAI v0.8.7 — Provider-native Function Calling

## Mục tiêu

v0.8.7 thay bộ planner JSON tự chế của v0.8.5 bằng function/tool calling gốc của nhà cung cấp AI. OpenAI dùng function tools của Responses API; Gemini dùng function declarations của Generate Content API.

Mục tiêu không phải tăng quyền tự chủ của model. Native function call vẫn chỉ tạo một proposal. Registry, schema validation, permission policy, confirmation và execution vẫn thuộc ứng dụng PersonalAI.

## Luồng mới

1. Người dùng bật **Đề xuất công cụ**.
2. PersonalAI lấy catalog hiện tại từ `IToolRegistry`.
3. Mỗi internal tool được ánh xạ sang một provider-safe function name deterministic.
4. Catalog function được gửi trực tiếp cho provider đang active.
5. Provider có thể trả ngôn ngữ tự nhiên hoặc tối đa một native function call.
6. Function name do provider trả về được ánh xạ ngược về internal tool.
7. Arguments tiếp tục phải vượt qua `IToolInputValidator`.
8. Server tự lấy permission từ registry; model không được khai báo hay cấp permission.
9. Function call trở thành `ToolCallProposal` và chưa thực thi.
10. Người dùng bấm chạy; WRITE/DELETE vẫn phải xác nhận theo policy hiện có.

## OpenAI

`OpenAiChatService` gửi function tools qua Responses API:

- `type: "function"`;
- provider-safe `name`;
- `description`;
- JSON Schema `parameters`;
- `tool_choice: "auto"`;
- `parallel_tool_calls: false`.

PersonalAI chỉ chấp nhận tối đa một `function_call` trong một lượt. Arguments JSON do provider trả về được parse rồi validation lại ở server.

`strict` hiện được đặt `false` vì catalog PersonalAI có nhiều tham số optional. Schema validation của ứng dụng vẫn là lớp kiểm tra bắt buộc trước khi proposal được lưu.

## Gemini

`GeminiChatService` gửi catalog qua:

- `tools[].functionDeclarations`;
- `toolConfig.functionCallingConfig.mode = "AUTO"`.

PersonalAI đọc `functionCall.name` và `functionCall.args` từ response. Nếu Gemini trả nhiều function call trong một lượt, PersonalAI từ chối tạo proposal thay vì âm thầm chọn một thao tác.

## Provider-safe function names

Tên internal tool có dấu chấm như `workspace.read_text`, trong khi provider function name có ràng buộc chặt hơn.

PersonalAI tạo alias:

- bắt đầu bằng `pai_`;
- chỉ dùng chữ, số và dấu gạch dưới;
- phần dễ đọc được giới hạn độ dài;
- thêm SHA-256 suffix deterministic để tránh collision;
- mapping chỉ sống trong request planning và không thay đổi tên tool nội bộ.

Provider không thể gọi một tên ngoài mapping; unknown function name bị bỏ qua.

## Provenance

Proposal native có thêm metadata:

- `planningMode = "provider-native"`;
- `planningProvider`;
- `planningModel`.

Proposal tạo trực tiếp qua endpoint prepare vẫn có `planningMode = "manual"`.

UI hiển thị provenance để người dùng biết proposal đến từ native function calling của provider nào/model nào.

## Guardrails giữ nguyên

- Native function call chỉ là proposal.
- Không có silent execution.
- Không coi nội dung hội thoại là confirmation.
- WRITE / DELETE / EXTERNAL / SENSITIVE vẫn theo permission policy hiện có.
- Arguments luôn validate lại bằng schema server-side.
- Chỉ một proposal được chấp nhận mỗi lượt.
- Tool result vẫn tóm tắt local trước.
- Gửi tool result sang provider để synthesis vẫn cần xác nhận external riêng như v0.8.6.
- Không có autonomous loop.

## Khả năng tương thích

Nếu provider/model đang cấu hình không hỗ trợ native function calling, request planning có thể bị provider từ chối. PersonalAI không âm thầm hạ cấp sang planner JSON cũ vì điều đó sẽ làm provenance không còn chính xác. Người dùng vẫn có thể tắt **Đề xuất công cụ** và chat bình thường.

## Kiểm thử

- build và toàn bộ Memory/RAG/tool regression;
