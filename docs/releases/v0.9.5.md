# PersonalAI v0.9.5 — Context Manager

## Mục tiêu

v0.9.5 thêm **Context Manager** để PersonalAI không còn ghép Memory, Documents và Tasks vào prompt theo các luồng rời rạc.

Mỗi yêu cầu chat được đánh giá trong workspace hiện tại, sau đó chỉ những mục đủ liên quan và nằm trong ngân sách context mới được đưa vào lời gọi AI.

## Chiến lược

Context Manager dùng chiến lược:

`workspace-scoped-budgeted-context-v1`

Nguyên tắc:

- chỉ đọc dữ liệu trong workspace hiện tại;
- Documents dùng hybrid search hiện có;
- Memory tiếp tục dùng bộ chọn memory liên quan;
- Tasks được chấm điểm theo mục tiêu, kế hoạch, trạng thái, bước hiện tại và mức khớp với câu hỏi;
- mỗi nhóm có ngân sách riêng và toàn bộ context có ngân sách tổng;
- không tự gọi tool, không tự chạy task và không mở rộng quyền thực thi.

## Ngân sách context

Ngân sách mặc định:

- tổng: 7.600 ký tự;
- Documents: tối đa 4.400 ký tự trong chat thông thường;
- Documents-only: tối đa 6.500 ký tự;
- Memory: tối đa 1.800 ký tự;
- Tasks: tối đa 1.400 ký tự;
- tối đa 4 document chunks;
- tối đa 4 memories;
- tối đa 3 tasks.

Ngân sách tính trên dữ liệu được chọn, không tính phần hướng dẫn hệ thống bao quanh context.

## Documents

Context Manager gọi Hybrid Search trong workspace hiện tại và chọn các chunk có liên quan cao nhất.

Khi tài liệu được đưa vào prompt:

- tài liệu được coi là dữ liệu tham khảo không đáng tin cậy về mặt instruction;
- câu lệnh nằm trong tài liệu không được coi là system instruction;
- nguồn vẫn được đánh số [1], [2], ...;
- ChatResponse vẫn trả `sources` để UI mở đúng tài liệu/đoạn.

Chế độ `documents-only` vẫn được giữ: nếu không có nguồn đủ liên quan, hệ thống không bổ sung kiến thức ngoài tài liệu.

## Memory

Memory được chọn từ các memory:

- đang bật;
- chưa hết hạn;
- chưa stale;
- được bộ chọn memory đánh giá liên quan đến yêu cầu hiện tại.

Context report không chứa nguyên văn memory. UI chỉ thấy loại memory, ngày cập nhật và lý do được chọn.

## Tasks

Context Manager có thể đưa task liên quan vào context chat.

Task context chỉ gồm thông tin tham khảo như:

- mục tiêu;
- trạng thái;
- kế hoạch;
- bước hiện tại;
- kết quả gần nhất nếu có.

Task context **không** cấp quyền chạy task và không kích hoạt tool.

Các task đang running/planned/interrupted được ưu tiên hơn task completed khi cùng mức liên quan.

## Context report

`ChatResponse` có thêm trường `context`.

Report gồm:

- workspace hiện tại;
- strategy;
- số Memory/Documents/Tasks được chọn;
- ngân sách tối đa và đã dùng;
- metadata an toàn của từng mục;
- lý do mục đó được chọn.

Report không chứa nguyên văn Memory hoặc payload của Task.

## Context Preview API

Endpoint mới:

`POST /api/context/preview`

Endpoint này chạy Context Manager nhưng không gọi nhà cung cấp AI.

Nó trả:

- context report;
- danh sách document sources đã chọn.

Có thể dùng để kiểm tra retrieval, budget và workspace isolation mà không tốn AI request.

## UI

Mỗi câu trả lời AI có thể hiển thị một khối:

`Ngữ cảnh đã chọn`

Khối này cho biết:

- số trí nhớ;
- số tài liệu;
- số tác vụ;
- ngân sách context đã sử dụng;
- lý do lựa chọn từng mục.

UI lưu context report cùng conversation metadata để vẫn xem được sau reload.

## An toàn

v0.9.5 không tăng mức tự động hóa:

- tool proposal vẫn chạy trước Context Manager như v0.9.4;
- Context Manager không gọi tool;
- task được đưa vào context chỉ là dữ liệu tham khảo;
- WRITE/DELETE vẫn cần xác nhận;
- không scheduler;
- không parallel task execution;
- không agent loop tự trị;
- không lấy dữ liệu xuyên workspace.

## Tương thích

- API cũ vẫn hoạt động.
- `UseTaskContext` mặc định là `true`.
- Memory/Documents có thể tắt bằng các cờ hiện có.
- Workspace v0.9.4 tiếp tục là ranh giới dữ liệu.
- Các service grounding cũ vẫn được giữ để tương thích nội bộ; chat chính đi qua Context Manager.

## Bước tiếp theo

Bản sau có thể tiếp tục theo roadmap bằng cách nâng Context Manager từ lựa chọn context tĩnh sang quản lý context theo phiên, có đánh giá chất lượng lựa chọn, nén lịch sử và quan sát mức sử dụng token/ký tự.
