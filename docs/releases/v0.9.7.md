# PersonalAI v0.9.7 — Undo Foundation

## Mục tiêu

v0.9.7 bổ sung **Undo Foundation** trên nền Audit v0.9.6.

Mục tiêu không phải là “mọi hành động đều có nút quay lại”, mà là chỉ cung cấp hoàn tác khi PersonalAI có đủ **pre-action state** và có thể chứng minh trạng thái hiện tại vẫn phù hợp để áp dụng inverse operation.

Không có hoàn tác tự động.

## Luồng an toàn

Với thao tác đủ điều kiện:

```
chuẩn bị hành động
    ↓
chụp pre-action state
    ↓
lưu undo pending
    ↓
chạy tool
    ↓
tool thành công
    ↓
lưu post-condition / checksum
    ↓
undo = available
```

Khi người dùng yêu cầu hoàn tác:

```
GET assessment
    ↓
kiểm tra trạng thái hiện tại
    ↓
người dùng xác nhận
    ↓
kiểm tra lại guard
    ↓
thực hiện inverse
    ↓
undo = undone
```

Nếu file hoặc đường dẫn đã thay đổi sau hành động gốc, PersonalAI từ chối hoàn tác thay vì ghi đè dữ liệu mới.

## Các thao tác được hỗ trợ

### workspace.write_text

- `create`: hoàn tác bằng cách xóa file vừa tạo, chỉ khi SHA-256 vẫn khớp.
- `overwrite`: lưu nội dung trước hành động và khôi phục lại, chỉ khi file hiện tại vẫn khớp post-action SHA-256.
- `append`: dùng cùng cơ chế snapshot + guard như overwrite.

### workspace.create_directory

Nếu hành động thực sự tạo thư mục mới, có thể hoàn tác bằng cách xóa thư mục đó **chỉ khi thư mục vẫn rỗng**.

Nếu thư mục đã tồn tại trước đó thì không tạo undo record.

### workspace.delete

- file tối đa 512 KB: lưu snapshot bytes và có thể khôi phục nếu đường dẫn vẫn trống;
- thư mục rỗng: có thể tạo lại nếu đường dẫn chưa bị dùng lại.

Không lưu snapshot file lớn hơn giới hạn.

### workspace.move

v0.9.7 hỗ trợ inverse cho **file move**:

- vị trí nguồn cũ phải vẫn trống;
- file tại vị trí đích phải còn tồn tại;
- SHA-256 phải khớp trạng thái sau lần move;
- thư mục cha của vị trí cũ phải còn tồn tại.

Di chuyển thư mục chưa có auto-undo trong bản này vì chưa có fingerprint cây thư mục đủ chặt.

## Phạm vi Tool Framework

Undo được tích hợp quanh `IToolExecutionService`, vì vậy các thao tác đủ điều kiện chạy qua:

- direct tool execution;
- tool proposal/orchestration;
- Task Engine;

đều có thể tạo undo record mà không cần mỗi caller tự triển khai lại logic snapshot.

`ToolExecutionResponse` có thêm:

```
undoId
```

Nếu hành động không đủ điều kiện hoàn tác, trường này là null.

## Storage

Undo metadata và snapshot nhỏ được lưu local bằng SQLite:

```
%LOCALAPPDATA%\PersonalAI\Undo\undo.db
```

Có thể override bằng:

```
Undo:Root
```

Giới hạn:

- thời gian khả dụng: 7 ngày;
- tối đa 500 record;
- query tối đa 100 record;
- snapshot tối đa 512 KB.

Snapshot không được trả qua API danh sách.

Pending record không được commit sau 10 phút sẽ chuyển sang abandoned và bỏ snapshot. Điều này tránh coi một hành động bị gián đoạn là chắc chắn có thể hoàn tác.

## API

### Danh sách

```
GET /api/undo
```

### Kiểm tra trước khi hoàn tác

```
GET /api/undo/{undoId}/assessment
```

Trả `canUndo` và lý do nhưng không thay đổi dữ liệu.

### Thực hiện

```
POST /api/undo/{undoId}/execute
Content-Type: application/json

{
  "confirmed": true
}
```

Không xác nhận trả 403.

Guard không còn đúng trả 409.

Undo ID chỉ được đọc và chạy trong workspace đã tạo ra nó.

## Audit

Audit Foundation ghi thêm:

- `undo.available`
- `undo.execute`

Reason dùng mã cố định:

- `reversible-tool-action`
- `user-confirmed-undo`
- `undo-expired`
- `undo-not-available`
- `undo-precondition-failed`

Audit không lưu snapshot.

## UI

Sidebar có mục **Hoàn tác**.

Danh sách chỉ hiển thị metadata an toàn:

- loại inverse;
- đường dẫn;
- tool gốc;
- trạng thái;
- thời hạn.

Trước khi chạy, UI gọi assessment và hiển thị lý do an toàn. Sau đó người dùng phải xác nhận bằng dialog của ứng dụng.

Không dùng browser `confirm()`.

## Workspace isolation

Undo record được gắn `WorkspaceId`.

Một workspace:

- không nhìn thấy undo record của workspace khác;
- không thể gọi execute bằng undo ID của workspace khác;
- áp dụng inverse bằng chính filesystem root của workspace hiện tại.

## Ngoài phạm vi

v0.9.7 chưa tự động hoàn tác:

- directory move;
- file delete lớn hơn 512 KB;
- Documents/RAG mutations;
- Memory mutations;
- external/sensitive actions;
- chuỗi nhiều action như một transaction;
- rollback nhiều bước tự động.

Không có “undo all” và không có background rollback.

## Tương thích

- Audit v0.9.6 vẫn append-only qua public API.
- Tool Activity Log vẫn giữ nguyên.
- Safe Retry và Task persistence không đổi.
- Undo không làm tool READ có side effect.
- WRITE/DELETE vẫn cần confirmation như trước.
- Undo bản thân cũng cần confirmation.

## Bước tiếp theo

Sau Undo Foundation, roadmap có thể chuyển sang **v1.0 — Stable Personal AI Core**: hardening toàn bộ Memory, RAG, Tools, Tasks, Workspace, Context, Audit và Undo trước khi trao thêm quyền điều khiển hệ thống.
