# PersonalAI v1.1.0 — Controlled Computer Use

## Mục tiêu

v1.1.0 mở capability đầu tiên sau Stable Core: **Computer Use có kiểm soát**.

Bản này không biến PersonalAI thành desktop agent tự trị. Mục tiêu chỉ là tạo nền computer-use có ranh giới rõ:

- quan sát desktop cục bộ;
- hai thao tác điều khiển giới hạn;
- permission riêng;
- confirmation bắt buộc;
- Tool Framework / Audit / Task Engine tiếp tục là lớp kiểm soát;
- không click, không gõ phím, không chụp màn hình và không chạy shell.

Backend điều khiển hiện chỉ hỗ trợ **Windows interactive session**.

## Release contract

- Version: `1.1.0`
- API contract: `1`
- Channel: `controlled`

API contract vẫn là 1 vì thay đổi của v1.1 là additive. Stable Core v1.0 không bị thay đổi semantics.

Capability contract thêm:

```json
{
  "controlledModules": ["computer-use"]
}
```

`computer-use` được chuyển khỏi `reservedModules`, nhưng chưa được coi là stable module.

## Permission mới

Tool Framework thêm:

```text
COMPUTER
```

Quyền này luôn cần explicit confirmation.

Các permission hiện tại:

- READ
- WRITE
- DELETE
- EXTERNAL
- SENSITIVE
- COMPUTER

Computer-control tool dùng `COMPUTER` cùng các permission liên quan thay vì tạo một đường thực thi riêng ngoài Tool Framework.

## Computer status API

Endpoint mới:

```http
GET /api/computer/status
```

Trả:

- version;
- platform;
- Windows có được hỗ trợ hay không;
- process có đang ở interactive session hay không;
- danh sách computer capability đang khả dụng;
- giới hạn của phiên bản.

Endpoint này chỉ đọc trạng thái cục bộ và không gọi model AI.

## Read-only computer tools

### computer.screen.info

Permission:

```text
READ
```

Đọc:

- primary screen width/height;
- virtual desktop bounds;
- số màn hình.

Không chụp nội dung màn hình.

### computer.cursor.position

Permission:

```text
READ
```

Chỉ đọc tọa độ cursor.

### computer.windows.list

Permissions:

```text
READ
SENSITIVE
```

Luôn cần confirmation vì window title và process name có thể làm lộ dữ liệu nhạy cảm.

Tool chỉ liệt kê top-level visible window có title và trả tối đa 50 cửa sổ.

### computer.window.active

Permissions:

```text
READ
SENSITIVE
```

Luôn cần confirmation.

Chỉ trả metadata của foreground window, không chụp pixels hay đọc nội dung control bên trong cửa sổ.

## Controlled actions

### computer.window.focus

Permissions:

```text
WRITE
COMPUTER
SENSITIVE
```

Luôn cần confirmation.

Tool chỉ yêu cầu Windows chuyển foreground tới một visible window ID đã biết.

Không click và không gửi keyboard input.

Windows có thể từ chối chuyển focus theo foreground policy của hệ điều hành; trường hợp đó tool thất bại thay vì bypass restriction.

### computer.cursor.move

Permissions:

```text
WRITE
COMPUTER
```

Luôn cần confirmation.

Tool chỉ di chuyển cursor tới tọa độ nằm trong virtual desktop hiện tại.

Không click chuột.

## Những gì cố ý chưa có

v1.1.0 **không** có:

- screenshot capture;
- OCR màn hình;
- mouse click;
- scroll;
- keyboard key press;
- text typing;
- clipboard read/write;
- app launching;
- shell / PowerShell / CMD;
- arbitrary process execution;
- desktop automation loop;
- background computer control;
- automatic confirmation.

Những capability này có rủi ro cao hơn và phải được thiết kế riêng nếu thêm sau.

## Privacy

Window title và process metadata được coi là `SENSITIVE`.

Do Tool Orchestration đã có guard:

- output của tool có SENSITIVE permission không tự được gửi lại provider AI để synthesis/native continuation;
- người dùng phải xác nhận trước khi tool chạy.

`computer.screen.info` và cursor position không đọc nội dung ứng dụng.

v1.1.0 không capture pixels.

## Audit

Computer Use chạy qua `IToolExecutionService`, do đó tiếp tục đi qua:

- Tool Activity Log;
- Audit Foundation;
- permission policy;
- confirmation policy.

Không có endpoint computer-control riêng để bypass tool policy.

## Tasks

Task Planner có thể nhìn thấy computer tools trong Tool Catalog.

Điều này **không** làm task tự thực thi.

Nếu task chứa bước computer-control:

1. người dùng vẫn phải chủ động chạy step;
2. COMPUTER / WRITE / SENSITIVE permission được kiểm tra;
3. confirmation vẫn bắt buộc;
4. không có automatic multi-step execution.

## Platform behavior

### Windows interactive session

Các capability v1.1.0 có thể hoạt động.

### Windows không interactive

`/api/computer/status` báo không có capability active.

Tool không cố bypass session isolation.

### Linux / macOS

Backend computer-control trả trạng thái unsupported.

Stable Core vẫn ready; computer-use được coi là controlled capability chưa cấu hình trên platform đó.

CI hiện chạy Linux nên kiểm tra:

- service build cross-platform;
- status unsupported đúng contract;
- tool catalog có đúng permissions;
- action bị policy chặn nếu thiếu confirmation;
- Windows-only code không chạy trên Linux.

## Health / capabilities

`/api/system/health` có thêm module:

`computer-use`

Computer Use không được tính là điều kiện readiness của Stable Core.

Do đó máy không phải Windows vẫn có thể:

```text
ready = true
computer-use = unconfigured
```

`/api/system/capabilities` thêm:

- `controlledModules = ["computer-use"]`
- `computerControlRequiresConfirmation = true`
- `sensitiveComputerObservationRequiresConfirmation = true`

Các guardrail cũ vẫn giữ nguyên.

## UI

Sidebar có mục:

`Máy tính`

Panel chỉ hiển thị:

- platform;
- supported / interactive status;
- capability đang có;
- giới hạn;
- permission model.

Panel không trực tiếp click/focus/move desktop.

Các action vẫn phải đi qua Tool Framework để giữ cùng approval flow.

## Bước tiếp theo

Theo roadmap, sau Computer Use sẽ tới **v1.2 — Browser Agent**.

Browser capability không nên dùng desktop click mù làm nền mặc định. Nên có browser-specific observation/action contract riêng, URL/origin guard, navigation policy, confirmation cho external side effects và audit đầy đủ.
