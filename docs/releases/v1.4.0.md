# PersonalAI v1.4.0 — Controlled Software Development Agent

## Mục tiêu

v1.4.0 mở capability phát triển phần mềm đầu tiên phía trên Stable Core.

Mục tiêu không phải là trao terminal tự do cho AI. Software Development Agent chỉ có một tập thao tác đã đóng khung:

- inspect source workspace;
- tìm text trong source;
- đọc Git status;
- đọc Git diff;
- chạy dotnet restore;
- chạy dotnet build;
- chạy dotnet test.

Mọi development tool đi qua Tool Framework, permission, confirmation, Tool Activity và Audit.

Không có autonomous coding loop.

## Release contract

- Version: `1.4.0`
- API contract: `1`
- Channel: `controlled`

`controlledModules` gồm:

- `computer-use`
- `browser-agent`
- `connectors`
- `software-development`

## Permission mới

Tool Framework thêm:

`DEVELOPMENT`

Permission này luôn cần explicit confirmation.

Development source/process output cũng dùng `SENSITIVE` để tránh tự động gửi code/output ra provider AI mà không có external synthesis confirmation.

Permission contract hiện tại:

- READ
- WRITE
- DELETE
- EXTERNAL
- SENSITIVE
- COMPUTER
- BROWSER
- CONNECTOR
- DEVELOPMENT

## Development status API

Endpoint:

```http
GET /api/development/status
```

Trả:

- workspace hiện tại;
- git có trong PATH hay không;
- dotnet có trong PATH hay không;
- capability đang đăng ký;
- limits;
- shell/process/git-write guardrails.

Endpoint chỉ kiểm tra local executable availability, không chạy build/test.

## Tool: dev.workspace.inspect

Permissions:

- READ
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Tool quét source tree trong workspace và trả:

- số file đã quét;
- project manifests;
- ngôn ngữ phát hiện được;
- root files;
- truncated state.

Bỏ qua các directory phổ biến:

- .git
- bin
- obj
- node_modules
- dist
- build
- coverage
- target
- .vs
- .idea
- .vscode
- __pycache__

Giới hạn mặc định:

- tối đa 2.000 file.

Không đi qua symlink/reparse point.

## Tool: dev.search.text

Permissions:

- READ
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Tìm chuỗi trong source text bằng code nội bộ, không gọi grep/ripgrep/shell.

Giới hạn:

- tối đa 400 file được xét;
- mỗi file tối đa 512 KB;
- tối đa 100 hit;
- preview tối đa 260 ký tự;
- chỉ các extension source/text được allowlist.

## Tool: dev.git.status

Permissions:

- READ
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Lệnh cố định:

```text
git -c core.fsmonitor=false status --short --branch --untracked-files=normal --ignore-submodules=all
```

Không nhận arbitrary git arguments.

Repository phải có `.git` directory thực nằm trong workspace.

Git worktree/gitfile trỏ ra ngoài workspace chưa được hỗ trợ.

## Tool: dev.git.diff

Permissions:

- READ
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Lệnh được đóng khung với:

- `--no-ext-diff`
- `--no-textconv`
- `--ignore-submodules=all`
- `--no-color`
- `--unified=3`

Có thể chọn staged hoặc unstaged.

Không có pathspec/arbitrary argument từ tool input.

Git process còn đặt:

- `GIT_TERMINAL_PROMPT=0`
- `GIT_PAGER=cat`
- `PAGER=cat`
- `GIT_OPTIONAL_LOCKS=0`

## Tool: dev.dotnet.restore

Permissions:

- READ
- WRITE
- EXTERNAL
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Chỉ nhận target:

- .sln
- .slnx
- .csproj
- .fsproj
- .vbproj

Target phải nằm trong workspace và không đi qua symlink.

Không nhận arbitrary CLI arguments.

Restore có thể truy cập package feed và thực thi MSBuild logic của project, nên được coi là external/code-execution capability.

## Tool: dev.dotnet.build

Permissions:

- READ
- WRITE
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Lệnh tương đương:

```text
dotnet build <target> --no-restore --nologo --configuration <Debug|Release> --verbosity minimal
```

Không có arbitrary argument injection.

Build có thể thực thi MSBuild targets/tasks từ project, vì vậy vẫn là code execution có kiểm soát.

## Tool: dev.dotnet.test

Permissions:

- READ
- WRITE
- SENSITIVE
- DEVELOPMENT

Luôn cần confirmation.

Chạy:

```text
dotnet test <target> --no-restore --nologo --configuration <Debug|Release> --verbosity minimal
```

Test code là executable project code.

Không retry tự động.

## Process boundary

Development Agent không dùng:

- shell command string;
- `cmd /c`;
- `powershell -Command`;
- `sh -c`;
- arbitrary executable name từ tool input;
- arbitrary process arguments từ tool input.

Process được tạo bằng `ProcessStartInfo.ArgumentList`.

Executable chỉ là các tên cố định:

- `git`
- `dotnet`

Process timeout:

- git: 15 giây;
- dotnet restore: 110 giây;
- dotnet build: 110 giây;
- dotnet test: 170 giây.

Khi timeout/cancel, PersonalAI cố gắng kill toàn bộ process tree.

## Output boundary

Process output tối đa:

`48.000 ký tự`

Phần dư bị truncate.

Workspace absolute root được thay bằng `.` trước khi output được trả lại.

Development output được coi là `SENSITIVE`.

## File editing

Software Development Agent không tạo một đường ghi file mới.

Nó tiếp tục dùng Workspace file tools đã có:

- workspace.read_text;
- workspace.write_text;
- workspace.create_directory;
- workspace.move;
- workspace.delete.

Nhờ vậy:

- path sandbox giữ nguyên;
- WRITE/DELETE confirmation giữ nguyên;
- SHA-256 guard giữ nguyên;
- Undo Foundation vẫn áp dụng cho các mutation đủ điều kiện.

## Task Engine

Task Planner có thể nhìn thấy development tools.

Điều này không làm coding task tự chạy.

Mỗi step:

- phải được người dùng chủ động execute;
- DEVELOPMENT permission được kiểm tra;
- confirmation bắt buộc.

Safe Retry chặn mọi step có DEVELOPMENT permission khỏi retry preparation.

## Health và capabilities

`/api/system/health` có module:

`software-development`

Nếu git hoặc dotnet có trong PATH, module có thể healthy.

Nếu cả hai không có:

`software-development = unconfigured`

Capability này không quyết định Stable Core readiness.

Safety contract thêm:

- `developmentUseRequiresConfirmation = true`
- `developmentArbitraryShellEnabled = false`
- `developmentGitWriteActionsEnabled = false`
- `developmentArbitraryProcessEnabled = false`

Limits contract thêm:

- maximum scanned files: 2.000;
- maximum search hits: 100;
- maximum process output: 48.000 ký tự.

## Ghi chú an toàn

`dotnet build` và `dotnet test` vẫn có thể chạy code do project định nghĩa, ví dụ MSBuild tasks hoặc test code.

v1.4 kiểm soát **cách process được khởi động**, target path, arguments, permission và confirmation; nó chưa cung cấp OS/container sandbox cho project code.

Vì vậy chỉ nên chạy development process trên workspace/repository mà người dùng tin cậy.
