# PersonalAI v1.8.0 — Controlled Automation

## Mục tiêu

v1.8.0 thêm **Automation** theo roadmap gốc.

Automation không biến PersonalAI thành autonomous agent. Scheduler chỉ tiến một task đã tồn tại, mỗi lần đến lịch tối đa một step và không tự xác nhận bất kỳ side effect nào.

Boundary quan trọng:

- người dùng phải tạo automation rõ ràng;
- automation chỉ tham chiếu task đã tồn tại trong cùng workspace;
- background auto-run chỉ áp dụng cho tool local, READ-only, không cần confirmation;
- WRITE / DELETE / EXTERNAL / SENSITIVE / COMPUTER / BROWSER / CONNECTOR / DEVELOPMENT không được background auto-confirm;
- Decision Engine recommendation không tự tạo hoặc chạy automation;
- crash giữa lúc automation chạy chuyển automation sang interrupted và disabled để người dùng review.

## Automation model

Một automation gồm:

- automation ID;
- workspace ID;
- name;
- task ID;
- schedule kind;
- start time;
- optional interval;
- next run;
- enabled state;
- runtime state;
- last run metadata;
- run count.

Schedule kinds:

```text
once
interval
```

States:

```text
scheduled
running
paused
awaiting-confirmation
completed
failed
interrupted
```

## Schedule limits

- tối đa 50 automation / workspace;
- interval tối thiểu 5 phút;
- interval tối đa 10.080 phút (7 ngày);
- scheduler poll mặc định 30 giây;
- mỗi scheduler tick chỉ lấy tối đa 1 automation due, nên toàn hệ thống tiến tối đa 1 task step nền mỗi tick.

Automation start time phải nằm trong khoảng từ 24 giờ trước đến 365 ngày tới.

## Persistence

Storage mặc định:

```text
%LOCALAPPDATA%\PersonalAI\Automation\automations.db
```

Override:

```text
Automation:Root
Automation__Root
```

SQLite dùng WAL và busy timeout.

Automation được lưu theo workspace.

Không có auto-delete lịch cũ để tránh âm thầm mất automation configuration.

## Crash recovery

Trước khi gọi Task Engine, automation được persist sang:

```text
state = running
```

Nếu app dừng trong lúc state đang là `running`, lần khởi động tiếp theo store chuyển record sang:

```text
enabled = false
state = interrupted
lastRunStatus = interrupted
```

Scheduler không tự retry record đó.

Người dùng phải kiểm tra task rồi explicit resume.

## Background scheduler

`AutomationBackgroundService` poll store mỗi 30 giây.

Scheduler chạy serial qua coordinator và chỉ lấy 1 automation due mỗi tick để:

- giữ invariant một scheduler tick chỉ tiến tối đa một task step nền;
- tránh nhiều automation cùng lúc thay đổi shared workspace context;
- giữ mỗi invocation có workspace header riêng;
- tránh concurrency làm lẫn `IHttpContextAccessor` workspace context.

Background execution tạo một scoped service context riêng và gắn:

```http
X-PersonalAI-Workspace: <automation-workspace>
```

trước khi resolve Task Engine.

Sau khi chạy xong, HttpContext trước đó được restore.

## Một step mỗi tick

Automation không gọi vòng lặp task.

Mỗi invocation chỉ gọi tối đa:

```text
ITaskEngineService.ExecuteNextAsync(...)
```

một lần.

Vì vậy:

```text
automationRunsAtMostOneTaskStepPerTick = true
automaticMultiStepExecution = false
```

Interval automation phải chờ lịch kế tiếp trước khi tiến step tiếp theo.

One-time automation kết thúc sau đúng một safe step, ngay cả khi task còn step khác.

## Auto-run allowlist

Một task step chỉ được chạy nền nếu current tool definition thỏa tất cả:

1. `LocalOnly = true`;
2. có ít nhất một permission;
3. toàn bộ permission là `READ`;
4. `RequiresConfirmation = false`;
5. không permission nào thuộc nhóm explicit-confirmation.

Nếu không thỏa, automation chuyển sang:

```text
awaiting-confirmation
enabled = false
```

và Task Engine không được gọi.

Đây là defense-in-depth ngoài policy check bên trong ToolExecutionService.

## Không auto-confirm

Automation coordinator luôn gọi Task Engine với:

```text
confirmed: false
```

Không có code path scheduler nào gọi `confirmed: true`.

Ngay cả `run-now` từ UI chỉ xác nhận việc kích hoạt automation; confirmation đó không được chuyển thành confirmation của task step.

Nếu task step cần confirmation, kết quả vẫn là:

```text
awaiting-confirmation
```

Người dùng phải mở Tasks, kiểm tra và thực thi step bằng flow hiện có.

## Dependencies

Automation tôn trọng:

- task-to-task dependencies;
- step-to-step dependencies.

Nếu dependency chưa hoàn tất:

- không chạy tool;
- automation giữ enabled;
- state vẫn scheduled;
- next run được dời lại có giới hạn;
- audit ghi blocked.

Automation không bỏ qua dependency graph.

## Terminal task states

Nếu task:

- completed → automation completed;
- failed → automation failed/disabled;
- cancelled → automation failed/disabled;
- interrupted → automation interrupted/disabled.

Automation completed hoặc failed không thể dùng `run-now` để hồi sinh.

Nếu muốn chạy lại logic, người dùng phải review task và tạo/khôi phục flow phù hợp.

## Run-now semantics

`run-now` cho phép người dùng kích hoạt scheduler ngay thay vì chờ nextRunAt.

Nó không bypass:

- workspace isolation;
- task dependencies;
- step dependencies;
- READ/local allowlist;
- task-step confirmation.

Completed/failed automation không được run-now lại.

## Audit

Audit agent mới:

```text
automation
```

Các action chính:

- `automation.create`
- `automation.enable`
- `automation.disable`
- `automation.resume`
- `automation.run-now`
- `automation.run`
- `automation.delete`

Run result có thể gồm:

- succeeded;
- blocked;
- denied;
- failed;
- interrupted.

Audit không lưu raw tool output của scheduler.

Tool Activity / Task Engine tiếp tục ghi execution metadata theo flow hiện có khi một safe step thực sự chạy.

## Decision Engine boundary

v1.7 recommendation không có quyền thực thi.

v1.8 giữ nguyên boundary:

```text
decision recommendation
        ≠
automation permission
```

Không có endpoint:

- decision → schedule;
- decision → create automation;
- decision → execute automation.

Muốn tự động hóa một recommendation, người dùng phải tạo task/automation trong một request riêng và explicit confirmation.
