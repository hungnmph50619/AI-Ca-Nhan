# v1.9.0 — Reliability & Security Hardening

v1.9.0 là lớp hardening trước mốc v2.0. Bản này không mở thêm autonomous execution; mục tiêu là giảm rủi ro vận hành của các capability đã có từ v1.0–v1.8.

## Phạm vi

- API rate guard: 600 request/phút theo IP + workspace.
- Giới hạn 16 API request xử lý đồng thời.
- Chặn request API lớn hơn 12 MB.
- Runtime heartbeat + clean/unclean shutdown marker.
- Permission audit dùng chính `IToolPolicy`; tool rủi ro phải bị chặn nếu chưa có xác nhận.
- Backup snapshot cây dữ liệu PersonalAI mặc định.
- SQLite snapshot bằng `BackupDatabase`, tránh copy database đang mở.
- Giữ tối đa 5 archive, tối đa 20.000 file và 512 MB dữ liệu nguồn mỗi backup.
- Restore được queue và chỉ áp dụng ở startup tiếp theo.
- Restore dùng staging, tạo pre-restore backup và rollback nếu apply thất bại.
- File lock cross-process ngăn hai maintenance operation chạy đồng thời.
- Hardening trở thành stable health module.

## API

```http
GET  /api/hardening/status
GET  /api/hardening/permissions
GET  /api/hardening/backups
POST /api/hardening/backups
POST /api/hardening/restore
```

`POST /api/hardening/backups` và `POST /api/hardening/restore` yêu cầu `confirmed: true`.

## Recovery semantics

Restore không ghi đè dữ liệu của process đang chạy. Khi người dùng xác nhận restore:

1. backup được validate và copy vào vùng pending;
2. request restore được ghi bền vững;
3. app tiếp tục chạy và trả trạng thái `pending-restart`;
4. ở startup tiếp theo, hardening service validate/extract vào staging;
5. một pre-restore backup được tạo;
6. dữ liệu hiện tại được đưa vào rollback area;
7. staged data mới được apply;
8. nếu lỗi, rollback data được phục hồi.

## Security invariants

- Không bật autonomous agent loop.
- Không bật parallel tool calls.
- Không tự xác nhận WRITE/DELETE/EXTERNAL/SENSITIVE/COMPUTER/BROWSER/CONNECTOR/DEVELOPMENT.
- Permission audit báo violation nếu policy thật cho phép một tool rủi ro chạy với `confirmed=false`.
- Zip restore kiểm tra path traversal, số file và tổng kích thước giải nén.
- Backup/restore dùng maintenance lock cross-process.

## Giới hạn hiện tại

Backup v1.9 bao phủ cây dữ liệu mặc định dưới `%LOCALAPPDATA%\PersonalAI`. Các store được redirect ra ngoài cây này bằng cấu hình `Workspace:Root`, `Tasks:Root`, `Audit:Root`, `Undo:Root`, `Connectors:Root`, `Companion:Root`, `LifeContext:Root` hoặc `Automation:Root` chưa được gom tự động vào cùng archive.

v1.9 cũng kế thừa task recovery và automation interrupted-recovery đã có ở các bản trước; bản này không tạo một cơ chế thứ hai chồng lên chúng.

## Tiêu chí trước v2.0

- build/CI phải xanh;
- permission audit không có violation;
- health endpoint nhận diện hardening;
- backup/restore luôn yêu cầu confirmation;
- failure khi restore không được làm mất rollback data;
- crash marker không được làm app tự thực hiện side effect.
