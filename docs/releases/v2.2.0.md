# v2.2.0 — Controlled Agent Orchestration

v2.2.0 bổ sung **workflow tuần tự có xác nhận của người dùng** trên Agent Framework v2.1.7. Đây là orchestration thực: backend gọi lần lượt 2–3 executable agent đã được người dùng **chọn và xác nhận trước**, trả kết quả từng bước và tùy chọn chuyển đầu ra giới hạn sang agent kế tiếp. Đây **không** phải autonomous agent loop, tự phân công từ Planner, parallel agent, tự chạy tool hoặc pipeline chỉnh sửa mã.

## Giao diện và API

Trong **Agents → Workflows · v2.2.0**:
1. Chọn agent và nhập mục tiêu của bước 1, bước 2; tùy chọn thêm bước 3.
2. Ở từng bước nhận, bật checkbox riêng nếu muốn chuyển tối đa 1.600 ký tự từ đầu ra bước trước. Mặc định **không chuyển**.
3. Context bổ sung (Knowledge, Memory, Tasks, Life Context) mặc định **tắt**; người dùng bật nguồn phù hợp.
4. Kiểm tra và tích xác nhận **toàn bộ workflow đã chọn**, sau đó bấm chạy. UI hiển thị kết quả hoàn tất theo thứ tự và bước bị dừng, nếu có.

```http
GET  /api/agents/orchestration/status
POST /api/agents/orchestration/execute
```

Ví dụ payload:

```json
{
  "confirmSelectedWorkflow": true,
  "steps": [
    { "agentId": "security.security-reviewer", "goal": "Review a proposed operation" },
    { "agentId": "security.security-reviewer", "goal": "Check prior review", "includePreviousOutput": true }
  ],
  "useKnowledge": false,
  "useMemory": false,
  "useTaskContext": false,
  "useLifeContext": false
}
```

Cấu trúc `AgentWorkflowResponse` bao gồm workflowId, workspaceId, status (`completed` hoặc `stopped`), các step result thực tế, số bước yêu cầu, failedStep khi có và các cờ no-tool/no-auto-selection/no-persistence/no-parallel.

## Quy tắc thực thi

- Validate **toàn bộ chuỗi** trước khi chạy: 2–3 bước, mỗi agent phải có trong registry, mỗi goal không trống và không quá 4.000 ký tự, không thể chuyển output ở bước 1. Chưa xác nhận workflow sẽ bị trả HTTP 400, **không chạy agent nào**.
- Agent ID, goal và handoff do người dùng khai báo; mô hình không tự chọn/thêm/đổi agent giữa các bước.
- Mỗi bước chạy qua `IAgentFrameworkService.ExecuteAsync` và audit hiện có; orchestration còn ghi audit các event workflow bằng identifier, **không ghi raw goal/output**. Tối đa một workflow tại cùng thời điểm và từng agent vẫn theo gate một lần gọi.
- Chỉ chuyển output của bước **ngay trước** nếu checkbox của bước nhận đã được bật, tối đa 1.600 ký tự, có nhãn rõ là dữ liệu chỉ đọc không phải chỉ dẫn hay permission. Không có shared queue hoặc lưu workflow tự động.
- Nếu một bước lỗi, workflow trả `stopped`, giữ các step đã hoàn tất và không chạy các bước còn lại. Cancellation được truyền tới từng agent.
- Không chuyển workspace trong cùng chuỗi; workflow gắn với workspace được xác định khi bắt đầu.

## Giới hạn an toàn và riêng tư

- Chọn agent dùng AI provider hoặc bật context có thể gửi goal, context và output đã opt-in đến AI provider đã cấu hình. Không nhập password, token hoặc dữ liệu nhạy cảm vào workflow; **nhãn dữ liệu không bảo đảm mô hình bỏ qua mọi prompt injection**.
- Handoff không cấp quyền thực thi: không tool execution, task creation, file write, external action, tự xác nhận hoặc đổi permission. Vẫn cần người dùng và permission/confirmation gate riêng khi một capability khác thực hiện side effect.
- Mốc này hỗ trợ **explicit bounded handoff**, không có model-driven automatic delegation, agent-initiated messaging, parallel agents, shared task queue, background workflow scheduler hoặc autonomous loop.
- Không khẳng định Agent Orchestration có thể tự truy cập ChatGPT, thay đổi chính mã nguồn, tự kiểm thử và merge PR.
- Thử nghiệm CI với hai Security Agent chạy cục bộ xác nhận tính tuần tự và opt-in handoff; chất lượng mô hình AI hoặc khả năng chống prompt injection chưa được chứng minh chỉ bằng smoke test.
