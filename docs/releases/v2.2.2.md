# v2.2.2 — Orchestration Reliability

This milestone adds **mandatory review of the exact output preview before each opted-in agent handoff**. A 2–3-step workflow remains sequential and user-selected. No agent gains tool execution, automatic delegation, file modification or authority to self-approve.

## Review checkpoint

When a completed step is followed by an opted-in handoff, the server validates its output with the v2.2.1 credential-pattern guard and returns `awaiting-review`, one completed-step result, and a checkpoint containing the exact preview (up to 1,600 characters), receiving agent, SHA-256 digest, opaque one-time token and expiry. The receiving agent **has not run** yet. The UI renders the preview with explicit approve/decline choices and a separate confirmation checkbox. Approval posts `/api/agents/orchestration/resume` with workflow ID, token and preview digest. Only after server verification does the workflow run the receiving agent. Decline stops the workflow without transfer.

Tokens are cryptographically random, single-use, limited to one workspace and preview digest; invalid tokens do not consume the checkpoint. A checkpoint expires after 10 minutes; at most eight may be pending. Pending state is **server memory only**, is lost on restart and is not a durable queue. Previously completed outputs may be included in API responses and kept temporarily for resumption; do not use workflows with secrets. Credential screening is limited and does not replace user review.

The 120-second workflow budget measures active execution across segments, excluding time waiting at review checkpoints. Each actively running agent step still has a cooperative 50-second budget. Cancellation relies on provider/I/O honoring cancellation; it is not guaranteed to stop uncooperative operations immediately. Invalid handoffs, timeout, cancellation, approval replay and denial do not run later steps.

## API

```http
GET  /api/agents/orchestration/status
POST /api/agents/orchestration/execute
POST /api/agents/orchestration/resume
```

`AgentWorkflowResponse` gains `handoffCheckpoint` and can return `awaiting-review`. `AgentOrchestrationStatusResponse` exposes `mandatoryContentReviewEnabled`, `maximumPendingReviewMinutes=10`, `maximumPendingWorkflows=8`, `resumableAcrossServerRestart=false`.

## Test coverage and limitations

CI tests an explicit checkpoint, incorrect grant, successful resume, replay rejection, explicit decline, previous validation, and no-tool boundaries. No configured AI provider is used in CI, so real provider cancellation/prompt injection behavior and exhaustive secret detection have not been established. This is a user-reviewed workflow, **not autonomous agent-to-agent messaging**.
