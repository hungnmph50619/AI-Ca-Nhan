# v2.5.2 — Data Cleaning

Roadmap yêu cầu Data Cleaning loại:

- duplicates;
- bad examples;
- secrets;
- corrupt data.

Bản này làm việc trên **một dataset ID + source version cụ thể** và không bao
giờ sửa snapshot nguồn.

API:

`POST /api/model-lab/data-cleaning`

## Preview trước, apply sau

Mặc định `createCleanedVersion = false`: chỉ trả cleaning report.

Để ghi kết quả thành immutable version mới phải có:

- `createCleanedVersion = true`
- `confirmCreateCleanedVersion = true`

Có thể truyền `expectedLatestVersion` để giữ concurrency guard của Dataset
Store.

## Deterministic cleaning rules

### Duplicate
Item được canonicalize JSON (object property sort ổn định) và SHA-256.
Exact canonical duplicate sau item đầu tiên bị loại.

### Bad example
Rule bảo thủ:

- top-level null;
- string rỗng/whitespace;
- array rỗng;
- object rỗng.

Không đánh giá chất lượng ngữ nghĩa bằng AI ở bước này.

### Secret
Loại item nếu phát hiện high-confidence signal:

- field name như password/secret/api_key/access_token/authorization/private_key;
- private-key PEM marker;
- Bearer token pattern;
- một số API-key pattern có cấu trúc rõ.

Cleaner không đưa secret value vào report; report chỉ ghi reason + fingerprint.

### Corrupt
Loại item nếu:

- JsonValueKind Undefined;
- nesting sâu hơn 32;
- tổng string content mỗi item vượt 200.000 ký tự;
- có Unicode replacement character hoặc control character bất thường.

## Output

Report trả:

- source/kept/removed counts;
- counts theo duplicate/bad-example/secret/corrupt;
- tối đa 250 removal records;
- source index + reason + fingerprint;
- version mới + SHA-256 nếu apply.

Bước tiếp theo theo roadmap là **v2.5.3 — Training Job Foundation**, đóng băng
DatasetVersion + SHA-256 + training config trước khi nối training provider.
