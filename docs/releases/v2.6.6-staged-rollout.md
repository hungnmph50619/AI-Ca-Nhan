# v2.6.6 — Triển khai thử từng bước

Bản này bổ sung rollout state bền vững cho candidate đã vượt Promotion Gate.

## Luồng

Promotion Gate approved-for-staging
→ candidate
→ staging
→ canary

v2.6.6 cố tình dừng ở canary.

Không có đường:

candidate → production

hoặc:

staging → production

## Bắt đầu rollout

Request phải có:

- promotionGateDecisionId;
- confirmStartRollout=true;
- stagingTrafficPercent=0.

Promotion Gate phải có:

- decision=approved-for-staging;
- eligibleForStaging=true.

Candidate phải đang ở stage candidate.
Production baseline phải đang ở stage production.

Khi bắt đầu:

- Model Registry chuyển candidate → staging;
- rollout state được lưu;
- trafficPercent=0;
- productionMutationPerformed=false.

## Chuyển sang canary

Chỉ cho phép:

staging → canary

Request cần:

- targetStage=canary;
- canaryTrafficPercent từ 1 đến 25;
- confirmAdvance=true.

Model Registry chuyển staging → canary và rollout state lưu traffic percent.

## Không cho production

v2.6.6 chặn:

- targetStage=production;
- targetStage=completed;
- candidate → canary trực tiếp;
- canary traffic > 25%;
- rollout không có explicit confirmation.

Production baseline vẫn giữ stage production.

## Persistence

Rollout state được lưu theo workspace tại:

`ModelLab/Rollouts/rollouts-{workspace}.json`

Mỗi state giữ:

- rollout ID;
- promotion gate decision ID;
- candidate model version ID;
- production model version ID;
- family;
- stage;
- traffic percent;
- productionMutationPerformed;
- timestamps.

## API

- `GET /api/model-lab/rollouts/status`
- `GET /api/model-lab/rollouts`
- `GET /api/model-lab/rollouts/{rolloutId}`
- `POST /api/model-lab/rollouts/start`
- `POST /api/model-lab/rollouts/{rolloutId}/advance`

## Audit

Bắt đầu rollout ghi:

`model-lab.rollout.start`

Chuyển stage ghi:

`model-lab.rollout.advance`

## Safety

Status công bố:

- `directProductionPromotionEnabled=false`
- `persisted=true`
- `explicitConfirmationRequired=true`

Traffic percent ở v2.6.6 là rollout state/policy metadata. Bản này chưa triển khai runtime traffic router thật, nên không tuyên bố đã chuyển phần trăm request production thực tế.

## Kiểm thử tự động

Workflow `model-lab-v266.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. seed production + candidate + Promotion Gate approved;
5. thiếu confirm rollout bị chặn;
6. candidate → staging;
7. staging traffic = 0;
8. thử staging → production bị chặn;
9. canary > 25% bị chặn;
10. staging → canary 10% thành công;
11. candidate registry stage = canary;
12. production baseline vẫn production;
13. rollout state được lưu và đọc lại.
