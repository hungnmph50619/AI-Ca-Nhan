# v2.6.9 — Bảo vệ code đang sửa

Bản này bảo vệ working tree của người dùng khỏi bị Development Agent ghi đè và bổ sung agent worktree cô lập.

## Mục tiêu

- không làm mất thay đổi chưa commit của người dùng;
- không tự reset;
- không cần checkout branch của agent trong working tree chính;
- agent sửa code trong worktree riêng;
- dirty agent worktree không bị cleanup cưỡng bức.

## Agent worktree

Worktree của agent được tạo dưới:

`.personalai-worktrees/{worktreeId}`

Branch agent bắt buộc có tiền tố:

`experiment/`

Ví dụ:

`experiment/roadmap-v2-6-10`

Main working tree có thể đang dirty; Git worktree mới vẫn được tạo từ Git ref đã chọn mà không sửa file đang mở của người dùng.

## Dirty-tree protection

Các thao tác Git từ v2.6.8 như checkout/create branch/pull vẫn yêu cầu worktree sạch.

v2.6.9 bổ sung thêm:

- không cleanup worktree đang dirty;
- không dùng `git worktree remove --force`;
- không dùng `git reset`;
- không dùng `git reset --hard`;
- không tự stash hoặc drop thay đổi của người dùng;
- không xóa agent worktree nếu còn code chưa commit.

## Roadmap Autopilot

RoadmapAutopilot giờ ưu tiên worktree riêng.

Khi chạy version tiếp theo:

1. xác định experiment branch;
2. tìm worktree đang tồn tại của branch đó;
3. nếu chưa có thì tạo worktree riêng từ BaseBranch;
4. mọi source edit đi vào worktree;
5. restore/build/test chạy trong worktree;
6. version check chạy trong worktree;
7. repo chính không bị checkout hoặc overwrite.

Nếu worktree cũ đang dirty mà không có checkpoint để resume, Autopilot từ chối tiếp tục thay vì ghi đè.

BaseBranch không còn bị ép chỉ là main/master, vì chuỗi roadmap có thể tiếp tục từ experiment branch/version hiện tại.

## Workspace scan

`.personalai-worktrees` được DevelopmentAgent bỏ qua khi scan/search workspace mặc định để tránh:

- duplicate search result;
- đếm cùng source hai lần;
- đưa cả repo agent vào context ngoài ý muốn.

Autopilot vẫn có thể đọc/ghi trực tiếp worktree bằng path đã biết.

## API

- `GET /api/development/worktrees/status`
- `GET /api/development/worktrees?repositoryPath=...`
- `POST /api/development/worktrees`
- `DELETE /api/development/worktrees`

## Create worktree

Request cần:

- repositoryPath;
- branch;
- startPoint;
- worktreeId;
- confirmCreateWorktree=true.

Worktree path luôn bị giới hạn trong workspace.

## Remove worktree

Request cần:

- repositoryPath;
- worktreePath;
- confirmRemoveWorktree=true.

Chỉ path nằm dưới `.personalai-worktrees` được phép cleanup.

Trước khi remove, service chạy Git status.

Nếu worktree dirty:

`400 Bad Request`

và toàn bộ file được giữ nguyên.

## Audit

Tạo worktree:

`development.worktree.create`

Cleanup:

`development.worktree.remove`

Audit cleanup ghi rõ:

`dirty:false;force:false`

## Safety status

Worktree status công bố:

- `worktreeIsolationEnabled=true`;
- `dirtyTreeOverwriteProtection=true`;
- `automaticResetEnabled=false`;
- `cleanupRequiresConfirmation=true`.

Development capabilities có thêm:

`git-worktree-isolation`

## Kiểm thử tự động

Workflow `development-v269.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. tạo Git repo thật;
5. tạo thay đổi chưa commit trong repo chính;
6. ghi lại SHA-256 của file dirty;
7. tạo agent worktree khi repo chính vẫn dirty;
8. xác minh file dirty repo chính không đổi;
9. sửa code trong agent worktree;
10. cleanup dirty worktree bị chặn;
11. commit agent change;
12. cleanup worktree sạch thành công;
13. SHA-256 file dirty repo chính vẫn giống ban đầu;
14. repo chính vẫn báo file dirty;
15. không có reset operation;
16. capability worktree isolation được công bố.
