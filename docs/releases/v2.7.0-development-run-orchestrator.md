# v2.7.0 — Bộ điều phối quá trình phát triển

Bản này bổ sung DevelopmentRun state machine persisted để điều phối toàn bộ vòng đời phát triển từ phân tích đến đồng bộ local.

## State machine

Chuỗi stage cố định:

analysis
→ coding
→ testing
→ review
→ security
→ benchmark
→ push
→ ci
→ merge-policy
→ local-sync
→ completed

Terminal ngoài completed:

- failed
- cancelled

Không cho nhảy stage tùy ý.

Mỗi lần advance phải gửi:

- expectedCurrentStage;
- result;
- evidence tùy chọn;
- ciRunId tùy chọn.

Nếu expectedCurrentStage không khớp stage persisted hiện tại thì trả conflict.

## DevelopmentRun

Mỗi run lưu:

- run ID;
- workspace ID;
- goal;
- repository path;
- branch;
- roadmap version tùy chọn;
- stage;
- status;
- CI run ID tùy chọn;
- toàn bộ transition history;
- createdAt;
- updatedAt;
- completedAt.

## Persistence

Run được lưu theo workspace tại:

`Development/Runs/development-runs-{workspace}.json`

Write dùng temp file rồi replace.

Status công bố:

- `persisted=true`
- `resumable=true`
- `sideEffectsAutomatic=false`

Điều cuối có nghĩa v2.7.0 mới điều phối state; nó chưa tự động chạy coding/build/review/push khi advance. Các version 2.7.x tiếp theo sẽ lần lượt nối side effect thật vào từng stage.

## Resume

`POST /api/development/runs/{runId}/resume`

không chạy lại side effect.

Nó chỉ đọc state persisted và trả DevelopmentRun active hiện tại để caller biết cần tiếp tục từ stage nào.

Điều này giúp tránh chạy lặp side effect sau restart.

Terminal run không được resume.

## Duplicate active run

Không cho hai DevelopmentRun active trên cùng:

`repositoryPath + branch`

Run thứ hai bị HTTP 409.

Lease/worktree protection từ v2.6.9-v2.6.10 vẫn là lớp bảo vệ bên dưới khi side effect được nối vào orchestration sau này.

## API

- `GET /api/development/runs/status`
- `GET /api/development/runs`
- `GET /api/development/runs/{runId}`
- `POST /api/development/runs`
- `POST /api/development/runs/{runId}/advance`
- `POST /api/development/runs/{runId}/fail`
- `POST /api/development/runs/{runId}/cancel`
- `POST /api/development/runs/{runId}/resume`

## Audit

Các action:

- `development.run.create`
- `development.run.advance`
- `development.run.fail`
- `development.run.cancel`
- `development.run.resume`

Transition history cũng được persist trong chính DevelopmentRun.

## Capability

Development Agent công bố:

`development-run-orchestration`

## Safety

v2.7.0 không:

- tự push khi advance stage;
- tự merge;
- tự sửa source chỉ vì gọi resume;
- nhảy qua review/security/benchmark;
- resume terminal run;
- tạo hai active run trên cùng branch.

## Kiểm thử tự động

Workflow `development-v270.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. status version 2.7.0;
5. persisted/resumable=true;
6. sideEffectsAutomatic=false;
7. tạo DevelopmentRun ở analysis;
8. duplicate active run cùng branch bị 409;
9. analysis → coding;
10. expected stage sai bị 409;
11. coding → testing;
12. restart application;
13. resume trả đúng testing stage;
14. tiếp tục tuần tự review/security/benchmark/push/ci/merge-policy/local-sync;
15. run đạt completed;
16. history có đủ 10 transition;
17. completed run không resume được;
18. capability development-run-orchestration được công bố.
