# v2.7.1 — Danh sách việc cần cải tiến

Bản này bổ sung Improvement Backlog persisted cho Development subsystem.

## Nguồn backlog

Hỗ trợ 6 nguồn:

- error
- feedback
- ci
- benchmark
- security
- dependency

Mỗi backlog item phải có evidence truy vết được.

## Backlog item

Mỗi item lưu:

- ID;
- workspace ID;
- SHA-256 fingerprint;
- source type;
- title;
- description;
- priority;
- state;
- occurrence count;
- danh sách evidence;
- firstSeenAt;
- lastSeenAt;
- updatedAt.

## Evidence

Mỗi evidence lưu:

- evidence ID;
- source type;
- source ID;
- reference;
- summary;
- observedAt.

Ví dụ reference:

- `ci-run:{guid}`
- `log:planner-42`
- `security:finding-17`
- `benchmark:run-28`

Nhờ vậy DevelopmentRun sau này có thể truy ngược từ backlog item về bằng chứng tạo ra nó.

## Priority

Các mức:

- low
- medium
- high
- critical

Nếu cùng fingerprint xuất hiện lại với priority cao hơn, item được nâng lên mức cao hơn.

## State

Các trạng thái:

- open
- planned
- in-progress
- resolved
- dismissed

State change yêu cầu reason và có audit.

## Deduplication

Fingerprint được tạo từ canonical form của:

- source type;
- source ID;
- title;
- evidence reference.

Sau đó SHA-256 được tính để tạo fingerprint 64 ký tự hex.

Nếu fingerprint đã tồn tại:

- không tạo item mới;
- evidence mới được gộp;
- occurrence tăng;
- lastSeenAt được cập nhật;
- priority có thể được nâng.

Nếu chính evidence cũ được ingest lại y hệt:

- không tạo item;
- không tạo evidence duplicate;
- không tăng occurrence.

Điều này làm việc import trở nên idempotent.

## CI import

Endpoint:

`POST /api/development/improvements/import-ci`

đọc CI Monitor và import các run:

- state=completed;
- conclusion khác success.

Evidence CI giữ:

- CI run ID;
- repository;
- SHA/ref;
- conclusion;
- failure log excerpt nếu có.

Gọi import nhiều lần cho cùng CI run không làm tăng occurrence giả.

## Persistence

Backlog được lưu theo workspace:

`Development/Improvement/improvement-backlog-{workspace}.json`

Write sử dụng temp file rồi replace.

## API

- `GET /api/development/improvements/status`
- `GET /api/development/improvements`
- `GET /api/development/improvements/{itemId}`
- `POST /api/development/improvements`
- `POST /api/development/improvements/{itemId}/state`
- `POST /api/development/improvements/import-ci`

## Status

Status công bố:

- item count;
- active/open count;
- critical count;
- evidence count;
- `deduplicationEnabled=true`;
- `evidenceTraceable=true`;
- `ciImportEnabled=true`;
- supported sources.

## Audit

Các action:

- `improvement.backlog.create`
- `improvement.backlog.dedupe`
- `improvement.backlog.state`
- `improvement.backlog.import-ci`

Audit chỉ lưu metadata cần thiết, không copy toàn bộ evidence content.

## Capability

Development Agent công bố:

`improvement-backlog`

## Safety

v2.7.1 không:

- tự tạo DevelopmentRun từ backlog;
- tự sửa code khi backlog item xuất hiện;
- tự đóng item khi chưa có state update;
- tự merge item trùng nhưng khác source/reference;
- xóa evidence cũ khi dedupe.
