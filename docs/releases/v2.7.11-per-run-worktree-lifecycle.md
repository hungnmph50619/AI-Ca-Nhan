# v2.7.11 — Quản lý worktree riêng cho AI

Bản này bổ sung persisted worktree lifecycle gắn 1:1 với DevelopmentRun.

## Mục tiêu

Mỗi DevelopmentRun có một worktree riêng:

DevelopmentRun
→ persisted binding
→ isolated experiment worktree
→ coding/testing/review trên worktree đó
→ terminal run
→ cleanup an toàn

Không force remove và không xóa user work.

## Binding 1:1

DevelopmentRunWorktreeBinding lưu:

- binding ID;
- workspace ID;
- DevelopmentRun ID;
- repository;
- experiment branch;
- worktree path;
- start point;
- lifecycle state;
- dirty flag;
- created/updated/removed timestamps.

Một DevelopmentRun chỉ có một binding trong toàn lifecycle.

Nếu binding đã removed thì service không tự tạo worktree thứ hai cho cùng run.

## Ensure idempotent

Endpoint ensure:

- yêu cầu ConfirmCreateWorktree=true;
- run phải active;
- branch phải experiment/*;
- nếu chưa có binding thì tạo worktree:
  `.personalai-worktrees/run-{developmentRunId}`;
- nếu binding đã có và worktree thực tế còn tồn tại thì reuse cùng binding/path;
- nếu binding persisted nhưng worktree biến mất ngoài hệ thống thì state=missing và không tự tạo replacement.

Điều này tránh silently thay worktree sau khi state đã bị lệch.

## Self Coding integration

SelfCodingService từ v2.7.11 không còn tự tìm một worktree bất kỳ theo branch.

Nó gọi:

`IDevelopmentRunWorktreeService.EnsureAsync`

và chỉ ghi vào worktree binding của đúng DevelopmentRun.

Branch lease và SHA overwrite guard từ các version trước vẫn giữ nguyên.

## Lifecycle states

- active;
- cleanup-deferred-dirty;
- removed;
- missing.

Worktree đang được run sử dụng vẫn ở state=active kể cả khi source đang dirty trong lúc coding.

Chỉ cleanup attempt trên terminal run mới có thể chuyển sang cleanup-deferred-dirty.

## Cleanup gate

Cleanup yêu cầu:

- ConfirmCleanup=true;
- DevelopmentRun tồn tại;
- run đã terminal:
  - completed;
  - failed;
  - cancelled.

Active run không được cleanup.

## Dirty worktree protection

Trước cleanup, service đọc Git status của đúng bound worktree.

Nếu dirty:

- không gọi git worktree remove;
- state=cleanup-deferred-dirty;
- Dirty=true;
- worktree directory vẫn tồn tại;
- mọi file chưa commit vẫn còn.

Không dùng:

- --force;
- reset;
- clean;
- auto stash.

Sau khi user/agent xử lý dirty work, cleanup có thể retry.

## Clean cleanup

Nếu worktree sạch:

`git worktree remove <path>`

không có --force.

Binding được giữ lại trong persistence với:

- state=removed;
- Dirty=false;
- RemovedAt.

Giữ binding history giúp chứng minh run từng sở hữu worktree nào.

## Persistence

Binding được lưu theo workspace:

`Development/RunWorktrees/development-run-worktrees-{workspace}.json`

Write dùng temp file rồi replace.

## API

- `GET /api/development/run-worktrees/status`
- `GET /api/development/run-worktrees`
- `GET /api/development/run-worktrees/{runId}`
- `POST /api/development/run-worktrees/ensure`
- `POST /api/development/run-worktrees/cleanup`

## Status

Status công bố:

- oneWorktreePerRun=true;
- cleanupRequiresTerminalRun=true;
- dirtyCleanupBlocked=true;
- forceRemoveEnabled=false.

## Audit

Các action:

- `development.run-worktree.create`
- `development.run-worktree.cleanup-deferred`
- `development.run-worktree.cleanup`

Audit lưu run/binding/worktree metadata, không lưu source content.

## Capability

Development Agent công bố:

`per-run-worktree-lifecycle`

## Safety

v2.7.11 không:

- share một binding giữa nhiều DevelopmentRun;
- tự tạo worktree thứ hai sau khi binding đã removed;
- cleanup active run;
- force remove dirty worktree;
- reset/clean/stash user work;
- tự tạo replacement khi persisted binding bị missing;
- cho SelfCoding chọn arbitrary worktree cùng branch.

## Kiểm thử tự động

Workflow `development-v2711.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. tạo Git repo thật;
5. tạo 2 DevelopmentRun khác nhau;
6. ensure tạo 2 worktree path khác nhau;
7. binding ID khác nhau;
8. ensure lần hai của run1 reuse cùng binding/path;
9. chỉ có 2 binding;
10. cleanup active run bị chặn;
11. tạo untracked user-work.txt trong run1 worktree;
12. terminalize run1;
13. cleanup trả cleanup-deferred-dirty;
14. worktree vẫn tồn tại;
15. file user vẫn tồn tại;
16. SHA file user không đổi;
17. sau khi user work được xử lý, cleanup thành công;
18. run2 clean cleanup thành công;
19. main worktree vẫn ở main;
20. README main không đổi;
21. cả 2 binding được giữ với state=removed;
22. SelfCoding source dùng runWorktrees.EnsureAsync;
23. capability per-run-worktree-lifecycle được công bố.
