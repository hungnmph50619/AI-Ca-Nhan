# v2.7.12 — Khôi phục khi máy tắt giữa chừng

Bản này bổ sung restart-safe recovery cho DevelopmentRun.

## Mục tiêu

Sau restart/crash, hệ thống không chạy lại side effect chỉ vì DevelopmentRun vẫn đứng ở stage cũ.

Recovery dùng persisted evidence để reconcile state machine:

persisted DevelopmentRun
+ persisted stage report
→ validate evidence
→ advance state only
→ không replay side effect

## Nguyên tắc no-replay

Recovery không tự gọi lại:

- build/test;
- independent review;
- security scan;
- benchmark;
- git push;
- tạo Pull Request;
- CI trigger;
- merge API;
- checkout/pull local sync.

Nếu persisted evidence hợp lệ chứng minh side effect đã hoàn tất, recovery chỉ gọi DevelopmentRun.Advance với ID report cũ.

Nếu chưa có evidence hoàn tất, recovery giữ nguyên stage và trả nextAction để caller chạy đúng side effect.

## Reconciliable stages

Recovery có thể reconcile:

- testing;
- review;
- security;
- benchmark;
- push;
- ci;
- merge-policy;
- local-sync.

Analysis/coding không tự advance chỉ vì restart vì chưa có persisted completion artifact đủ mạnh để chứng minh side effect đã hoàn tất.

## Testing recovery

Nếu DevelopmentRun đang ở testing và có DevelopmentTestReport:

- đúng run;
- Succeeded=true;

recovery dùng report cũ để:

testing → review

Không chạy lại dotnet restore/build/test.

## Review recovery

Nếu có DevelopmentReviewReport:

- đúng run;
- Approved=true;

recovery:

review → security

Không gọi Reviewer Agent lần hai.

## Security recovery

Nếu có DevelopmentSecurityReport:

- đúng run;
- PromotionAllowed=true;
- HighRiskFound=false;

recovery:

security → benchmark

với SecurityReportId cũ.

Không quét source lần hai.

## Benchmark recovery

Nếu có DevelopmentBenchmarkReport:

- đúng run;
- Passed=true;

recovery:

benchmark → push

với BenchmarkReportId cũ.

Không chạy benchmark lại.

## Push/PR recovery

Nếu có DevelopmentGitHubReport:

- đúng run;
- branch khớp DevelopmentRun;
- Pushed=true;
- PullRequestCreated=true;

recovery:

push → ci

với GitHubReportId cũ.

Không git push và không tạo/reuse PR lại.

## CI recovery

Recovery ưu tiên CiRunId đã link trong DevelopmentRun.

Nếu chưa có, service tìm persisted CI success cùng experiment branch.

CI chỉ hợp lệ khi:

- state=completed;
- conclusion=success.

Recovery:

ci → merge-policy

Không trigger CI mới.

## Merge recovery

Nếu có DevelopmentMergePolicyReport:

- đúng run;
- Merged=true;

recovery:

merge-policy → local-sync

Không gọi GitHub merge API lần hai.

## Local sync recovery

Nếu có DevelopmentLocalSyncReport:

- đúng run;
- State=synced;
- Synced=true;
- DirtyTreeDetected=false;

recovery:

local-sync → completed

Không fetch/checkout/pull lần hai.

## Một bước reconcile mỗi invocation

Mỗi recovery invocation advance tối đa một stage.

Nếu stage tiếp theo cũng đã có persisted completion evidence:

`RecoveryRequired=true`

và:

`NextAction=reconcile-next-persisted-stage`

Caller có thể gọi recovery lần tiếp theo.

Thiết kế này giúp checkpoint progression rõ ràng và audit được từng bước.

## Unresolved stage

Nếu không có completion evidence:

- Advanced=false;
- SideEffectReplayed=false;
- stage giữ nguyên;
- NextAction chỉ ra việc cần làm.

Ví dụ:

- analysis → continue-analysis;
- coding → continue-coding-in-bound-worktree;
- testing → run-development-tests;
- push → push-and-create-pull-request;
- ci → wait-for-ci-or-request-repair.

## API

- `GET /api/development/recovery/status`
- `POST /api/development/recovery/run`

POST yêu cầu:

`ConfirmRecovery=true`

## Status

Status công bố:

- persistedStateUsed=true;
- sideEffectReplayEnabled=false;
- safeReconciliationEnabled=true;
- active run count;
- số run có evidence đủ để reconcile;
- danh sách reconciliable stages.

## Audit

Các action:

- `development.recovery.inspect`
- `development.recovery.reconcile`

Audit lưu:

- DevelopmentRun ID;
- stage before/after;
- evidence count;
- side-effect-replayed=false.

Không lưu source content hoặc credential.

## Capability

Development Agent công bố:

`restart-safe-recovery`

## Safety

v2.7.12 không:

- tự chạy lại side effect sau restart;
- tự push nếu đã có persisted push report;
- tự merge nếu đã có persisted merged report;
- tự local-sync nếu đã có persisted synced report;
- tự advance khi evidence không đủ;
- tự coi pending/failed CI là success;
- tự advance analysis/coding chỉ dựa trên suy đoán.

## Kiểm thử tự động

Workflow `development-v2712.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. status version 2.7.12;
5. sideEffectReplayEnabled=false;
6. tạo DevelopmentRun;
7. recovery ở analysis không advance;
8. đặt run ở push và persist GitHubReport đã push/PR;
9. restart app;
10. recovery push → ci;
11. không cần Git remote/GitHub API để recovery;
12. persist CI success;
13. restart app;
14. recovery ci → merge-policy;
15. persist merged policy report;
16. restart app;
17. recovery merge-policy → local-sync;
18. persist synced local-sync report;
19. restart app;
20. recovery local-sync → completed;
21. các report ID cũ được persist vào DevelopmentRun;
22. mọi RecoveryResult có SideEffectReplayed=false;
23. capability restart-safe-recovery được công bố.
