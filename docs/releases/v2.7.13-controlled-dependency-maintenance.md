# v2.7.13 — Tự bảo trì dependency

Bản này bổ sung Controlled Dependency Maintenance cho DevelopmentRun.

## Mục tiêu

Cập nhật dependency có kiểm soát trong isolated DevelopmentRun worktree rồi tiếp tục qua các gate:

- testing;
- review;
- security;
- benchmark.

Major upgrade rủi ro cao không được auto-apply.

## Scope v2.7.13

Service hỗ trợ PackageReference có Version tĩnh trong file .csproj.

Hỗ trợ hai dạng:

`<PackageReference Include="X" Version="1.2.3" />`

và:

`<PackageReference Include="X"><Version>1.2.3</Version></PackageReference>`

Không tự sửa version expression/property phức tạp nếu không đọc được version tĩnh.

## Plan trước khi apply

DependencyMaintenanceService tách hai bước:

plan
→ apply

Plan yêu cầu:

- DevelopmentRun tồn tại;
- run thuộc workspace hiện tại;
- run active;
- stage=coding;
- project path là .csproj tương đối an toàn;
- PackageReference tồn tại;
- current/target version là version số tĩnh được hỗ trợ;
- không downgrade;
- persisted worktree binding riêng của run.

Nếu worktree chưa có, plan có thể tạo qua DevelopmentRunWorktreeService khi có ConfirmCreateWorktree=true.

## SemVer classification

Upgrade được phân loại:

- patch;
- minor;
- major;
- same.

Risk mapping:

- patch → low;
- minor → medium;
- major → high.

## Major upgrade policy

Major plan luôn:

- AutomaticEligible=false;
- RequiresUserApproval=true;
- State=blocked-major.

Apply major mà không có:

`ConfirmMajorUpgrade=true`

bị HTTP 400.

Do đó major dependency không thể đi qua automatic path chỉ bằng ConfirmApply.

Người dùng vẫn có thể xác nhận major upgrade riêng; sau đó thay đổi vẫn phải đi qua toàn bộ DevelopmentRun gates.

## Patch/minor policy

Patch/minor có thể:

- AutomaticEligible=true;
- RequiresUserApproval=false.

Apply vẫn yêu cầu:

`ConfirmApply=true`

để việc ghi file không xảy ra ngoài ý muốn.

## Worktree isolation

Dependency file chỉ được đọc/ghi trong:

`DevelopmentRunWorktreeBinding.WorktreePath`

Main working tree không được sửa.

Plan persist worktree path và apply xác minh binding vẫn trùng plan.

Nếu binding đã removed hoặc bị đổi thì apply bị từ chối.

## Stale-plan / SHA guard

Plan lưu CurrentVersion.

Trước khi apply:

1. đọc lại project file;
2. tìm đúng PackageReference;
3. xác minh version hiện tại vẫn bằng CurrentVersion của plan;
4. tính SHA-256 của file vừa đọc;
5. WorkspaceFileService overwrite với expectedSha256.

Nếu project file bị sửa sau khi lập plan:

apply bị chặn

và không ghi đè thay đổi mới.

## Downgrade

Nếu TargetVersion thấp hơn CurrentVersion:

plan bị từ chối.

v2.7.13 không tự downgrade dependency.

## Required post-apply gates

Mỗi plan persist:

`RequiredPostApplyGates=[testing,review,security,benchmark]`

Dependency maintenance chạy ở stage=coding.

Sau apply, DevelopmentRun vẫn phải đi theo state machine:

coding
→ testing
→ review
→ security
→ benchmark

Các gate đã được enforcement bởi các version v2.7.4–v2.7.7.

Dependency service không bypass hoặc đánh dấu các gate đó pass.

## Persistence

Plan được lưu theo workspace:

`Development/DependencyMaintenance/dependency-maintenance-{workspace}.json`

Plan lưu:

- DevelopmentRun ID;
- worktree path;
- project path;
- package ID;
- current version;
- target version;
- upgrade kind;
- risk level;
- automatic eligibility;
- user approval requirement;
- state;
- resulting SHA-256;
- required post-apply gates;
- timestamps.

## API

- `GET /api/development/dependencies/status`
- `GET /api/development/dependencies/plans`
- `GET /api/development/dependencies/plans/{planId}`
- `POST /api/development/dependencies/plan`
- `POST /api/development/dependencies/apply`

## Status

Status công bố:

- majorAutoUpgradeAllowed=false;
- worktreeOnly=true;
- shaGuardEnabled=true;
- requiredPostApplyGates=[testing,review,security,benchmark].

## Audit

Các action:

- `development.dependency.plan`
- `development.dependency.apply`

Audit lưu:

- run;
- plan;
- package;
- old/new version;
- upgrade kind;
- automatic eligibility;
- resulting SHA.

Không lưu secret.

## Capability

Development Agent công bố:

`controlled-dependency-maintenance`

## Safety

v2.7.13 không:

- auto-apply major upgrade;
- downgrade dependency;
- sửa main working tree;
- update package ngoài DevelopmentRun coding stage;
- overwrite stale project file;
- bypass testing/review/security/benchmark;
- tự coi major upgrade là low-risk.

## Kiểm thử tự động

Workflow `development-v2713.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. tạo Git repo có .csproj và PackageReference;
5. tạo DevelopmentRun và đưa tới coding;
6. patch 1.2.3 → 1.2.4 được classify low/patch;
7. patch plan automaticEligible=true;
8. apply patch trong run worktree;
9. main .csproj giữ nguyên hash;
10. worktree .csproj có version mới;
11. major 2.4.0 → 3.0.0 được classify high/major;
12. major plan automaticEligible=false;
13. major plan requiresUserApproval=true;
14. major apply không ConfirmMajorUpgrade bị HTTP 400;
15. major dependency vẫn giữ version cũ;
16. lập minor plan rồi sửa file sau plan;
17. stale plan apply bị HTTP 400;
18. thay đổi mới không bị ghi đè;
19. status có applied/blocked-major counts đúng;
20. capability controlled-dependency-maintenance được công bố.
