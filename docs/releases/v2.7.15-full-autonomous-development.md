# v2.7.15 — Chế độ phát triển hoàn toàn tự động

Bản này bổ sung full autonomous development controller cho low-risk DevelopmentRun đủ điều kiện.

## Mục tiêu

Khép success path:

detect
→ analysis
→ coding
→ testing
→ review
→ security
→ benchmark
→ push
→ CI
→ merge-policy
→ local-sync
→ completed

Controller không có quyền bypass bất kỳ gate nào đã xây ở v2.7.0–v2.7.14.

## Eligible autonomous work

Nếu request không truyền DevelopmentRunId, controller chỉ tự chọn backlog item khi:

- priority=low;
- state=open hoặc planned;
- chưa có active DevelopmentRun cho cùng item;
- đã có root-cause diagnosis ở trạng thái diagnosed;
- verified hypothesis tồn tại.

Nếu chưa có verified diagnosis, item không được chọn.

Controller không tự bịa reproduction/hypothesis để đạt chữ "autonomous".

## Analysis

DevelopmentRun ở analysis chỉ được advance khi DiagnosisId:

- tồn tại;
- RootCauseDiagnosisService.IsDiagnosed=true.

Nếu chưa đủ:

`stopReason=awaiting-diagnosis`

## Autonomous coding

Khi DevelopmentRun vào coding:

1. đảm bảo persisted per-run worktree;
2. chỉ đọc tối đa 6 context file;
3. mỗi context file tối đa 15,000 ký tự;
4. gọi active AI provider khi ConfirmExternalAi=true;
5. model chỉ được trả tối đa 4 full-file replacement;
6. edit path bắt buộc thuộc context allowlist;
7. chỉ overwrite file đã tồn tại;
8. dùng SHA-256 guard trước khi ghi.

Blocked paths gồm:

- .git/*;
- .github/*;
- file có tên secret/credential;
- appsettings.Production.json.

Không cho AI tự create/delete file, chạy shell, commit hoặc push trong coding stage.

## Coding no-replay evidence

AutonomousCodingResult được persist theo workspace:

`Development/Autonomous/Coding/autonomous-coding-{workspace}.json`

Nếu AI đã ghi file nhưng emergency stop bật trước khi state machine advance:

- coding report vẫn tồn tại;
- lần sau controller reuse report;
- không gọi AI sửa source lần hai;
- chỉ advance coding → testing.

## Testing

Controller dùng DevelopmentAutoTestService.

Nếu chưa có persisted successful test report:

- restore thật;
- build thật;
- unit test thật;
- integration target nếu được cấu hình;
- regression evaluation.

Test fail:

`stopReason=gate-failed`

và không advance.

## Independent review

Controller dùng DevelopmentReviewService với:

- CodingAgentId=autonomous.coder;
- ReviewerId=quality.reviewer;
- ConfirmReview=true;
- ConfirmExternalReviewer phụ thuộc ConfirmExternalAi.

Coding agent vẫn không được tự approve.

## Security

Controller dùng DevelopmentSecurityService.

High-risk finding hoặc PromotionAllowed=false:

- pipeline dừng;
- không được benchmark/push.

## Benchmark

Controller dùng đủ benchmark gates từ v2.7.7:

- RAG;
- tool;
- task;
- agent;
- performance;
- resource.

Agent benchmark yêu cầu ConfirmExternalAi=true.

Benchmark fail thì pipeline dừng.

## Push + Pull Request

Push stage yêu cầu:

- ConfirmGitHubSideEffects=true;
- CredentialRef không rỗng;
- experiment/* branch;
- existing safety policy của LocalGitRepositoryService.

Controller dùng DevelopmentGitHubService.

Direct main/master push vẫn bị chặn ở tầng Git thấp.

## CI

Controller refresh CI qua GitHub report + CiMonitor.

Nếu CI chưa completed:

`stopReason=ci-pending`

Nếu CI failure và repairAttempts < 3:

- request đúng 1 repair attempt;
- dừng invocation;
- `stopReason=ci-repair-requested`.

Nếu đã đạt 3 repair attempt mà vẫn fail:

`stopReason=gate-failed`

Không retry vô hạn.

v2.7.15 không giả vờ đã sửa CI failure nếu chưa có source change/test cycle mới.

## Merge policy

Controller chỉ gọi automatic merge path với:

`riskLevel=low`

và vẫn truyền toàn bộ report IDs:

- independent review;
- security;
- benchmark;
- GitHub PR;
- CI.

Auto-merge chỉ xảy ra nếu:

`AllowLowRiskAutomaticMerge=true`

High-risk automatic merge vẫn bị cấm bởi DevelopmentMergePolicyService.

Nếu policy cần người dùng:

`stopReason=user-confirmation-required`

## Local sync

Controller dùng Safe Local Sync v2.7.10.

Nếu local tree dirty:

`stopReason=dirty-tree-deferred`

Không reset/clean/stash.

Chỉ synced report hợp lệ mới cho run completed.

## Emergency stop

Persisted emergency stop API:

- `GET /api/development/autonomous/emergency-stop`
- `POST /api/development/autonomous/emergency-stop`

Mutation yêu cầu:

`Confirm=true`

Khi stop active:

- autonomous invocation dừng trước stage tiếp theo;
- Transitions=0 nếu stop đã bật từ đầu;
- không gọi AI/GitHub/tool side effect mới.

Controller kiểm tra emergency stop trước mỗi stage và sau các side effect quan trọng.

## Transition budget

Mỗi invocation có:

`MaximumTransitions`

Hard maximum:

`20`

Điều này chặn runaway autonomous loop ngay cả khi mọi downstream system phản hồi tức thời.

## API

- `GET /api/development/autonomous/status`
- `GET /api/development/autonomous/emergency-stop`
- `POST /api/development/autonomous/emergency-stop`
- `POST /api/development/autonomous/run`

Autonomous run yêu cầu:

`ConfirmAutonomousRun=true`

External AI và GitHub side effects có confirmation riêng.

## Status contract

Status công bố:

- fullPipelineControllerEnabled=true;
- policyBypassAllowed=false;
- maximumTransitionsPerInvocation=20;
- maximumCodingEdits=4;
- maximumCiRepairAttempts=3;
- directMainPushAllowed=false;
- highRiskAutoMergeAllowed=false;
- pipeline đủ detect→local-sync.

## Result contract

AutonomousDevelopmentRunResult lưu trong response:

- DevelopmentRun ID;
- stage/status cuối;
- transitions;
- completed;
- emergencyStopped;
- policyBypassed;
- stopReason;
- từng stage step + evidence ID.

`PolicyBypassed` luôn false.

## Safety

v2.7.15 không:

- tự chọn backlog medium/high/critical;
- giả lập root-cause diagnosis;
- edit file ngoài context allowlist;
- overwrite file stale SHA;
- push main/master;
- bypass independent review;
- bypass security high-risk gate;
- bypass benchmark;
- bypass CI success;
- auto-merge high-risk;
- overwrite dirty local tree;
- retry CI vô hạn;
- tiếp tục khi emergency stop đang bật.

## Full autonomous benchmark

Workflow `development-v2715.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. status version 2.7.15;
5. policyBypassAllowed=false;
6. directMainPushAllowed=false;
7. highRiskAutoMergeAllowed=false;
8. coding edit hard limit=4;
9. CI repair hard limit=3;
10. tạo low-risk backlog item;
11. tạo reproduction + hypothesis + verified diagnosis thật qua API;
12. tạo DevelopmentRun có DiagnosisId;
13. seed persisted successful stage evidence để mô phỏng restart-safe completed side effects;
14. bật emergency stop;
15. autonomous invocation trả emergency-stop với 0 transition;
16. resume emergency stop;
17. controller đi 10 transition:
    analysis→coding→testing→review→security→benchmark→push→ci→merge-policy→local-sync→completed;
18. persisted coding evidence được reuse, không gọi AI lại;
19. persisted test/review/security/benchmark/push/merge/sync evidence được reuse;
20. CI success được correlate qua Development Event Bus;
21. result Completed=true;
22. PolicyBypassed=false;
23. từng action stage đều xuất hiện;
24. DevelopmentRun persist các report IDs;
25. backlog item chuyển resolved;
26. capability full-autonomous-development được công bố.

Benchmark này cố ý dùng persisted stage evidence cho side effects đã hoàn tất để đồng thời kiểm tra no-replay behavior của v2.7.12.

## Giới hạn được giữ rõ

"Fully autonomous" ở v2.7.15 nghĩa là controller có thể khép **eligible low-risk success path** mà không cần người dùng bấm từng stage.

Nó không có nghĩa hệ thống được phép:

- tự bịa diagnosis khi evidence chưa đủ;
- tự vượt qua failure;
- tự chấp nhận high-risk merge;
- bỏ qua confirmation cho external AI/GitHub;
- tự phá user work để hoàn thành pipeline.

CI failure path vẫn finite: request repair theo budget rồi dừng invocation. Source repair mới phải đi lại qua coding/testing/review/security/benchmark trước khi trở thành evidence hợp lệ.
