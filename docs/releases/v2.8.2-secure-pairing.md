# v2.8.2 — Ghép nối an toàn

Bản này bổ sung Secure Pairing challenge-response cho Android Companion và Device Hub.

## Mục tiêu

Ghép nối mới dùng:

one-time code / QR
→ challenge
→ device public key
→ ECDSA proof
→ token issuance
→ trusted device identity

Pairing code phải hết hạn và mã đã dùng không thể replay, kể cả sau restart.

## Secure pairing ticket

Local admin tạo ticket qua:

`POST /api/companion/admin/secure-pairing/start`

Request vẫn yêu cầu:

`confirmed=true`

Ticket trả:

- one-time code;
- workspace;
- random challenge;
- Hub public key;
- key algorithm;
- QR payload;
- expiry.

QR payload có dạng:

`personalai://pair/{base64url-json}`

và chứa dữ liệu public cần để thiết bị tạo proof.

## Pairing code

Code dài 12 ký tự, loại bỏ ký tự dễ nhầm.

Backend không persist plaintext code.

Store chỉ lưu:

`SHA-256(normalized-code)`

Claim lookup dùng fixed-time equality trên hash.

## Challenge proof

Thiết bị tự tạo ECDSA P-256 keypair.

Claim request gửi:

- code;
- device name;
- device public key;
- proof signature.

Canonical proof message:

`PersonalAI-SecurePairing-v1\n{code}\n{challenge}\n{hubPublicKey}`

Signature dùng:

- ECDSA P-256;
- SHA-256;
- DER/RFC3279 signature format.

Server import SubjectPublicKeyInfo và verify chữ ký trước khi trust device.

Biết code nhưng không có private key tương ứng với device public key không đủ để hoàn tất secure pairing.

## Hub pairing key

Mỗi ticket tạo một Hub ECDSA P-256 keypair.

Public key được trả cho thiết bị.

Private key chỉ được persist sau khi:

- export PKCS#8;
- Base64 encode;
- ASP.NET Core Data Protection;
- purpose `PersonalAI.SecurePairing.v1`.

Private-key byte buffer được zero sau protect/unprotect.

Trước claim, backend giải mã Hub private key và xác minh public key khớp ticket persisted.

## Replay protection

Secure pairing store persist cả pending và consumed ticket.

Khi proof hợp lệ, backend:

1. đánh dấu ticket `ConsumedAt`;
2. persist consumed state;
3. sau đó mới cấp Companion device/token/trust.

Nếu process chết sau bước 2, code vẫn bị consumed.

Đây là fail-closed behavior: user tạo ticket mới thay vì replay ticket cũ.

Replay cùng code:

`HTTP 400`

với trạng thái mã đã dùng.

Consumed state persist nên replay vẫn bị từ chối sau application restart.

## Expiry

TTL mặc định:

`300 seconds`

Config:

`SecurePairing:LifetimeSeconds`

Hard max:

`600 seconds`

Expired ticket bị từ chối trước khi tạo device/token/trust.

Status công bố TTL theo:

`PairingLifetimeSeconds`

## Trusted device

Chỉ secure pairing proof hợp lệ mới gọi:

`IDeviceIdentityService.EstablishTrust`

Device identity được cập nhật:

- PairedDevicePublicKey;
- PairedDeviceFingerprintSha256;
- TrustLevel=trusted;
- TrustedAt.

Nếu identity đã trusted bằng public key khác, backend từ chối thay key tự động.

## Hai public key khác nhau

v2.8.1 đã có Hub-managed identity keypair cho từng DeviceHubDevice.

v2.8.2 bổ sung peer/device-owned public key từ secure pairing:

- `PublicKey` = Hub-managed identity public key;
- `PairedDevicePublicKey` = public key do thiết bị chứng minh sở hữu;
- fingerprint tương ứng được lưu riêng.

Điều này tránh thay đổi identity key cũ và vẫn chứng minh được possession của device key mới.

## Legacy pairing

Các endpoint pairing cũ vẫn tồn tại để tương thích.

Legacy pairing:

- có token;
- có Device Hub identity;
- TrustLevel vẫn là `untrusted`.

Chỉ secure pairing challenge-response mới nâng trust thành `trusted`.

## Permission invariant

Trusted không đồng nghĩa có quyền chạy capability.

Sau secure pairing:

- PermissionsGranted=false;
- RemoteExecutionEnabled=false;
- Capabilities vẫn chưa tự cấp.

Capability permission thuộc v2.8.3.

## API

Local admin:

- `GET /api/companion/secure-pairing/status`
- `POST /api/companion/admin/secure-pairing/start`

Unauthenticated pairing claim over required secure transport:

- `POST /api/companion/secure-pairing/claim`

Companion capability thêm:

`secure-pairing`

## Persistence

File:

`secure-pairings.json`

Stored ticket gồm:

- ID;
- workspace;
- CodeSha256;
- challenge;
- HubPublicKey;
- EncryptedHubPrivateKey;
- created/expires;
- consumed timestamp;
- claimed device ID.

Store không chứa plaintext pairing code hay PEM private key.

State JSON corrupt thì service fail closed.

## Secure Pairing status

Status công bố:

- Version;
- Enabled;
- PairingLifetimeSeconds;
- ChallengeSignatureRequired=true;
- PairingCodeSingleUse=true;
- ConsumedCodesPersisted=true;
- ReplayProtectionSurvivesRestart=true;
- TrustedOnlyAfterProof=true;
- KeyAlgorithm=ECDSA-P256.

## Audit

Actions:

- `secure-pairing.start`
- `secure-pairing.claim`
- `device-identity.trust`

Audit không ghi plaintext pairing code hoặc private key.

## Safety

v2.8.2 không:

- trust device chỉ vì biết pairing code;
- reuse pairing code đã consumed;
- reuse expired code;
- lưu pairing code plaintext;
- lưu Hub private key plaintext;
- tự replace public key của trusted device;
- cấp capability permission;
- bật remote execution;
- coi legacy pairing là trusted.
