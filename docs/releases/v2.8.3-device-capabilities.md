# v2.8.3 — Khả năng từng thiết bị

Bản này bổ sung Device Capability Registry và permission enforcement theo từng thiết bị.

## Mục tiêu

Thiết bị có thể đăng ký các capability:

- git;
- build;
- gpu;
- gps;
- camera;
- notification;
- voice.

Nhưng capability đã đăng ký không đồng nghĩa được phép sử dụng.

Mọi access phải thỏa:

registered=true
+
permissionGranted=true

Nếu thiếu một điều kiện thì bị từ chối.

## Registry là nguồn sự thật về permission

DeviceIdentity.Capabilities chỉ là metadata về capability đã đăng ký.

Permission thực được lưu riêng trong DeviceCapabilityRegistration.

Do đó:

- identity có tên capability không tự cấp quyền;
- caller không được suy permission từ identity metadata;
- CheckAccess luôn đọc capability registry.

## Supported capability allowlist

v2.8.3 chỉ chấp nhận:

- git
- build
- gpu
- gps
- camera
- notification
- voice

Tên ngoài allowlist, ví dụ shell, bị từ chối.

Việc này tránh thiết bị tự khai báo arbitrary capability name rồi được pipeline sau hiểu nhầm.

## Registration

Local admin đăng ký capability bằng:

`POST /api/device-hub/admin/devices/{deviceId}/capabilities`

Request:

`ConfirmRegister=true`

Capability mới luôn mặc định:

`PermissionGranted=false`

Không có automatic grant.

## Explicit permission

Local admin thay đổi permission qua:

`POST /api/device-hub/admin/devices/{deviceId}/capabilities/{capability}/permission`

Request yêu cầu:

`ConfirmPermissionChange=true`

Không được grant permission nếu capability chưa đăng ký.

## Companion trust rule

Android/Companion device chỉ được grant permission=true khi identity:

`TrustLevel=trusted`

Nghĩa là:

- legacy pairing → untrusted → có thể register capability nhưng không thể grant;
- secure pairing v2.8.2 → trusted → local admin có thể grant.

Local PC/laptop/other do local admin register không bị bắt buộc secure pairing để admin grant vì thao tác permission được thực hiện trực tiếp từ local admin context.

## Access enforcement

Service:

`CheckAccess(workspaceId, deviceId, capability)`

trả:

- Registered;
- PermissionGranted;
- Allowed;
- Reason.

Các reason:

- capability-not-registered;
- permission-not-granted;
- allowed.

Companion endpoint:

`POST /api/companion/client/hub/capabilities/{capability}/authorize`

chỉ trả HTTP 200 khi Allowed=true.

Unregistered hoặc denied trả HTTP 403.

Đây là preflight enforcement contract để task router v2.8.4 và distributed execution các version sau tái sử dụng.

## Capability listing

Local admin:

- `GET /api/device-hub/capabilities/status`
- `GET /api/device-hub/devices/{deviceId}/capabilities`
- `GET /api/device-hub/admin/devices/{deviceId}/capabilities/{capability}/access`

Companion authenticated device:

- `GET /api/companion/client/hub/capabilities`
- `POST /api/companion/client/hub/capabilities/{capability}/authorize`

## Identity metadata sync

Khi capability được đăng ký, DeviceIdentity.Capabilities được đồng bộ bằng:

`IDeviceIdentityService.SetCapabilitiesMetadata`

Identity chỉ lưu danh sách registered capability, không lưu permission state.

Ví dụ:

camera registered + permission=false

thì identity vẫn có:

`Capabilities=["camera"]`

nhưng authorize vẫn HTTP 403.

## Persistence

Mỗi workspace có:

`device-capabilities-{workspace}.json`

Stored registration gồm:

- registration ID;
- workspace ID;
- device ID;
- capability;
- registered;
- permission granted;
- registered timestamp;
- permission update timestamp;
- updated timestamp.

Corrupt state fail closed bằng DeviceCapabilityValidationException.

## Status contract

DeviceCapabilityStatus công bố:

- Version;
- WorkspaceId;
- Registrations;
- GrantedPermissions;
- RegistrationRequired=true;
- ExplicitPermissionRequired=true;
- UnregisteredInvocationBlocked=true;
- CompanionTrustRequiredForPermissionGrant=true;
- AutomaticPermissionGrantEnabled=false;
- SupportedCapabilities.

## Companion capability

Companion client công bố:

`device-capabilities`

Đây là capability của API contract, không phải permission để camera/GPS/etc.

## Audit

Các action:

- `device-capability.register`
- `device-capability.permission`
- `device-identity.capabilities.sync`

Audit ghi device/capability/grant state nhưng không chứa device private key hoặc token.

## Safety

v2.8.3 không:

- auto-grant capability khi register;
- cho unregistered capability được gọi;
- cho registered-but-denied capability được gọi;
- grant remote Companion untrusted device;
- suy permission từ DeviceIdentity.Capabilities;
- cho arbitrary capability ngoài allowlist;
- bật remote tool execution chỉ vì capability được grant;
- route task sang device — phần đó thuộc v2.8.4.

## Kiểm thử tự động

Workflow `device-capabilities-v283.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. version 2.8.3;
5. RegistrationRequired=true;
6. ExplicitPermissionRequired=true;
7. UnregisteredInvocationBlocked=true;
8. AutomaticPermissionGrantEnabled=false;
9. allowlist đúng 7 capability;
10. secure-pair Android để có trusted identity;
11. camera chưa register → authorize HTTP 403;
12. register thiếu confirmation → HTTP 400;
13. register camera → permission=false;
14. camera registered nhưng chưa grant → authorize HTTP 403;
15. identity metadata có camera nhưng permissionsGranted vẫn false;
16. grant thiếu confirmation → HTTP 400;
17. explicit grant camera → permission=true;
18. camera authorize → HTTP 200;
19. arbitrary capability shell → HTTP 400;
20. legacy-pair Android → untrusted;
21. register notification cho legacy device;
22. grant permission cho untrusted Companion → HTTP 400;
23. untrusted notification authorize → HTTP 403;
24. Companion công bố device-capabilities;
25. registry persist camera grant + notification deny;
26. restart app;
27. camera permission vẫn tồn tại;
28. camera authorize sau restart vẫn HTTP 200.
