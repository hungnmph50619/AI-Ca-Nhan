# v2.8.4 — Phân việc đúng thiết bị

Bản này bổ sung Task Router chọn device theo capability permission, trust và availability.

## Mục tiêu

Task Router nhận:

- PersonalTask;
- required capability;

sau đó chọn đúng thiết bị theo:

capability registered
+
permission granted
+
trust phù hợp
+
device online

Thiết bị offline không được nhận task.

## Scope

v2.8.4 chỉ quyết định routing và persist route decision.

Bản này chưa:

- chạy tool trên remote device;
- chuyển agent context sang node khác;
- dispatch execution qua network.

Distributed execution thuộc v2.8.5.

## Routing request

Endpoint:

`POST /api/tasks/{taskId}/route`

Body:

- RequiredCapability;
- ConfirmRoute.

Routing decision được persist nên yêu cầu:

`ConfirmRoute=true`

## Eligible device

Một device chỉ Eligible=true khi:

1. ConnectionStatus=online;
2. trust boundary hợp lệ;
3. capability đã register;
4. permissionGranted=true;
5. DeviceCapabilityService.CheckAccess trả Allowed=true.

Nếu thiếu bất kỳ điều kiện nào thì device bị loại.

## Trust policy

Hai trust boundary được chấp nhận:

### Local admin device

Device có:

`Source=local-admin`

được coi là đã đi qua local-admin trust boundary.

Điều này phù hợp v2.8.3: PC/laptop/other local device có thể được local admin grant capability trực tiếp.

### Companion device

Device có:

`Source=companion`

phải có:

`DeviceIdentity.TrustLevel=trusted`

tức phải secure-pair qua v2.8.2.

Legacy-paired Android untrusted không được route task dù capability đã register.

## Availability

Router chỉ chấp nhận:

`ConnectionStatus=online`

Offline/unknown không Eligible.

LastSeen không được dùng làm tie-break.

Nó chỉ được Device Hub dùng để tính online/offline.

Điều này tránh routing thay đổi chỉ vì hai heartbeat lệch nhau vài mili giây.

## Deterministic ordering

Sau khi tính eligibility, candidates được sort ổn định theo:

1. trust-rank;
2. device-type-rank;
3. stable-device-id.

Trust rank:

- local-admin trust boundary → 0;
- secure-paired trusted Companion → 1;
- untrusted → 9.

Device type rank:

- pc → 0;
- laptop → 1;
- android → 2;
- other → 3.

Cuối cùng dùng DeviceId dạng stable GUID N string theo ordinal.

Với cùng state đầu vào, router chọn cùng một device.

## Vì sao local PC được ưu tiên

Một secure-paired Android có trust cryptographic mạnh, nhưng đối với task như build/git, local PC/laptop là execution boundary phù hợp và được local admin trực tiếp quản lý.

Vì vậy local-admin devices được rank trước trusted Companion khi cả hai đều đủ capability.

Việc chọn dựa theo workload/resource cụ thể hơn sẽ có thể mở rộng ở các version sau.

## Route decision

TaskRouteDecision persist:

- route ID;
- workspace;
- task ID;
- required capability;
- selected device ID/name/type;
- decision;
- reason;
- full candidate evaluation;
- routed timestamp.

Decision:

- routed;
- unroutable.

## Candidate explanation

Mỗi TaskRouteCandidate có:

- DeviceId;
- DeviceName;
- DeviceType;
- Source;
- TrustLevel;
- ConnectionStatus;
- CapabilityRegistered;
- PermissionGranted;
- Eligible;
- Reason;
- TrustRank;
- DeviceTypeRank.

Reason có thể là:

- eligible;
- device-offline;
- device-not-trusted;
- capability-not-registered;
- permission-not-granted.

## Unroutable

Nếu không có eligible device, router không chọn fallback nguy hiểm.

Response:

`HTTP 409`

với:

`Decision=unroutable`

và toàn bộ candidate reasons để caller biết cần:

- đưa device online;
- secure-pair;
- register capability;
- grant permission.

## API

- `GET /api/tasks/router/status`
- `GET /api/tasks/routes`
- `GET /api/tasks/{taskId}/route`
- `POST /api/tasks/{taskId}/route`

## Persistence

Mỗi workspace:

`task-routes-{workspace}.json`

State corrupt thì service fail closed bằng TaskRouterValidationException.

## Status contract

TaskRouterStatus công bố:

- DeterministicRouting=true;
- OfflineDevicesEligible=false;
- CapabilityPermissionRequired=true;
- CompanionTrustRequired=true;
- LocalAdminRegistrationAcceptedAsTrustBoundary=true;
- RouteDecisionPersisted=true;
- StableTieBreakOrder=[trust-rank,device-type-rank,stable-device-id].

## Audit

Action:

`task.device.route`

Audit ghi:

- task ID;
- capability;
- routed/unroutable;
- selected device nếu có;
- rank;
- stop reason.

## Safety

v2.8.4 không:

- route offline device;
- route unknown device;
- route Companion untrusted device;
- route capability chưa register;
- route capability chưa grant;
- tự cấp permission để route thành công;
- dùng heartbeat time làm nondeterministic tie-break;
- execute remote capability sau khi chọn device.

## Kiểm thử tự động

Workflow `task-router-v284.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. version 2.8.4;
5. deterministicRouting=true;
6. offlineDevicesEligible=false;
7. tạo PC local;
8. tạo laptop local;
9. heartbeat cả hai online;
10. register + grant build cho cả hai;
11. legacy-pair Android untrusted;
12. register build cho Android;
13. grant Android bị chặn vì untrusted;
14. tạo PersonalTask thật qua Task Engine;
15. route thiếu ConfirmRoute bị chặn;
16. route lần 1 chọn PC;
17. candidate PC/laptop đều eligible;
18. Android candidate bị device-not-trusted;
19. route lần 2 cùng state vẫn chọn đúng PC;
20. làm PC stale/offline;
21. route chuyển deterministic sang laptop;
22. làm laptop stale/offline;
23. router trả HTTP 409 unroutable;
24. không fallback sang Android untrusted;
25. route decisions được persist;
26. restart app;
27. latest route decision vẫn đọc được.
