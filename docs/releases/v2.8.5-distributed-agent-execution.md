# v2.8.5 — Agent chạy phân tán

Bản này nối Task Router v2.8.4 với một lifecycle distributed execution có kiểm soát: dispatch → claim → complete.

## Mục tiêu

Sau khi một PersonalTask đã được route tới thiết bị phù hợp, caller có thể tạo distributed agent execution cho một agent đã đăng ký trong Agent Framework.

Execution luôn có:

- correlation ID duy nhất;
- task ID;
- agent ID;
- required capability;
- context được xác nhận trước khi dispatch;
- device ID/name/type đã được Task Router chọn;
- trạng thái persisted.

## Permission không bị “mất” khi chuyển node

Quyền capability không chỉ được kiểm tra ở lúc route.

v2.8.5 kiểm tra lại capability ở ba thời điểm:

1. dispatch;
2. claim;
3. complete.

Nếu permission bị thu hồi, device offline, Companion mất trust hoặc device không còn tồn tại, lifecycle fail closed.

Một route decision cũ không tự động trở thành quyền thực thi lâu dài.

## Correlation ID

Mỗi execution có `CorrelationId` riêng.

Correlation ID được dùng xuyên suốt:

- dispatch;
- claim;
- complete;
- audit;
- persistence;
- API lookup sau restart.

Điều này cho phép nối execution giữa planner/developer/vision/mobile node mà không dựa vào state trong RAM.

## Dispatch

Endpoint:

`POST /api/tasks/{taskId}/distributed-executions`

Yêu cầu:

- task tồn tại và chưa kết thúc;
- agent ID đã đăng ký;
- task đã có route decision `routed`;
- required capability khớp route;
- selected device vẫn online;
- capability vẫn registered + granted;
- Companion vẫn trusted;
- `ConfirmDispatch=true`.

Context bị giới hạn 8.000 ký tự.

## Claim

Endpoint:

`POST /api/devices/{deviceId}/distributed-executions/{correlationId}/claim`

Chỉ đúng device đã route mới được claim.

Yêu cầu:

- execution đang `queued`;
- `ConfirmClaim=true`;
- device vẫn online;
- capability permission vẫn hợp lệ;
- Companion trust vẫn hợp lệ.

## Complete

Endpoint:

`POST /api/devices/{deviceId}/distributed-executions/{correlationId}/complete`

Yêu cầu:

- execution đã `claimed`;
- đúng device;
- `ConfirmComplete=true`;
- permission được kiểm tra lại lần cuối.

Kết quả có thể là:

- `succeeded`;
- `failed`.

Result summary bị giới hạn 8.000 ký tự.

## Persistence

Mỗi workspace dùng file riêng:

`distributed-agent-executions-{workspace}.json`

State corrupt thì service từ chối suy đoán execution.

## API

- `GET /api/tasks/distributed-execution/status`
- `GET /api/tasks/distributed-executions`
- `GET /api/tasks/distributed-executions/{correlationId}`
- `POST /api/tasks/{taskId}/distributed-executions`
- `POST /api/devices/{deviceId}/distributed-executions/{correlationId}/claim`
- `POST /api/devices/{deviceId}/distributed-executions/{correlationId}/complete`

## Audit

Các action mới:

- `agent.distributed.dispatch`;
- `agent.distributed.claim`;
- `agent.distributed.complete`.

Audit ghi correlation ID, device, capability và việc permission đã được revalidate.

## Safety

v2.8.5 không:

- tự route khi chưa có route decision;
- dispatch sang offline device;
- bỏ qua permission sau khi route;
- cho node khác claim execution;
- cho Companion untrusted nhận execution;
- tự cấp capability permission;
- tự chạy agent nếu chưa có node client thực thi lifecycle;
- tự merge/deploy production.

Lifecycle này là control plane cho distributed execution. Node runtime thực tế vẫn phải tuân thủ capability boundary và chỉ thực hiện execution đã claim.

## Kiểm thử tự động

Workflow `distributed-agent-v285.yml` kiểm tra:

1. restore;
2. build;
3. test;
4. version 2.8.5;
5. status contract;
6. local PC online + build capability granted;
7. PersonalTask được tạo;
8. Task Router chọn PC;
9. dispatch thiếu confirm bị chặn;
10. dispatch hợp lệ sinh correlation ID;
11. claim thiếu confirm bị chặn;
12. đúng device claim thành công;
13. thu hồi permission trước complete;
14. complete bị chặn khi permission đã thu hồi;
15. cấp lại permission;
16. complete thành công;
17. restart app;
18. execution vẫn đọc được theo correlation ID.
