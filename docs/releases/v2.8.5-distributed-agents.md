# v2.8.5 — Agent chạy phân tán

Bản này bổ sung distributed agent dispatch queue qua trusted Companion node.

## Mục tiêu

Cho agent execution được chuyển sang node phù hợp mà vẫn giữ:

- execution identity;
- correlation ID;
- required capability;
- capability permission snapshot;
- trust boundary;
- workspace boundary.

Acceptance chính:

- build/test đạt;
- execution có correlation ID;
- permission không mất khi chuyển node.

## Scope

v2.8.5 không giả lập remote process execution trong server.

Server thực hiện:

dispatch
→ persist execution
→ trusted node claim
→ node thực thi ngoài server
→ complete bằng cùng correlation ID
→ server re-check trust + permission
→ persist result

Remote transport hiện dùng authenticated Android Companion channel.

## Eligible node

Distributed dispatch chỉ chọn device khi:

- Source=companion;
- ConnectionStatus=online;
- DeviceIdentity.TrustLevel=trusted;
- required capability đã register;
- PermissionGranted=true;
- DeviceCapabilityService.CheckAccess Allowed=true.

Local-admin PC/laptop chưa được dùng làm remote transport vì v2.8.5 chưa có per-node authenticated transport riêng cho local device.

Điều này tránh route execution tới một device chỉ vì local record tồn tại nhưng node không có secure claim channel.

## Agent validation

AgentId bắt buộc tồn tại trong Agent Framework registry.

Goal dùng cùng giới hạn:

`AgentFrameworkLimits.MaximumGoalCharacters`

Ví dụ hiện có:

- planning.planner;
- development.developer;
- các registered agent khác trong framework.

Transport không tự tạo arbitrary agent ID.

## Required capability

Dispatch phải khai báo một capability trong allowlist v2.8.3:

- git;
- build;
- gpu;
- gps;
- camera;
- notification;
- voice.

Node selection deterministic:

1. chỉ eligible node;
2. device type rank;
3. stable DeviceId.

Offline/untrusted/denied node bị loại trước khi chọn.

## Correlation ID

Mỗi DistributedAgentExecution có hai ID:

- ExecutionId: identity của execution record;
- CorrelationId: identity xuyên transport boundary.

CorrelationId được giữ nguyên qua:

dispatch
→ claim envelope
→ complete request
→ persisted result
→ audit.

Complete có CorrelationId sai bị từ chối.

## Permission snapshot

Khi dispatch, server persist:

- Capability;
- RegistrationId;
- Registered;
- PermissionGranted;
- PermissionUpdatedAt.

Snapshot chứng minh permission tại thời điểm dispatch.

Nhưng snapshot không phải authorization token bất biến.

Server vẫn re-check permission hiện tại khi:

- node claim execution;
- node complete execution.

Điều này bảo đảm permission không bị "mất" khi context chuyển node.

## Revoke giữa chừng

Nếu:

dispatch
→ node claim
→ local admin revoke capability
→ node complete

thì result không được chấp nhận.

Execution chuyển:

`status=blocked`

với:

`permission-or-trust-revoked-before-complete`

Permission mới nhất thắng snapshot cũ.

## Claim

Authenticated node gọi:

`GET /api/companion/client/distributed/next`

Server:

1. xác định CompanionDevice từ bearer token;
2. heartbeat Device Hub;
3. xác minh identity vẫn trusted;
4. lấy queued execution của đúng TargetDeviceId;
5. re-check capability permission;
6. chuyển queued → running;
7. trả DistributedAgentEnvelope.

Envelope có:

- ExecutionId;
- CorrelationId;
- AgentId;
- Goal;
- RequiredCapability;
- PermissionSnapshot;
- CreatedAt.

## Complete

Node gọi:

`POST /api/companion/client/distributed/{executionId}/complete`

Body:

- CorrelationId;
- Succeeded;
- Message;
- Error.

Server kiểm tra:

- execution thuộc đúng authenticated device;
- correlation ID khớp;
- status=running;
- device vẫn trusted;
- capability vẫn allowed.

Sai bất kỳ điều kiện nào thì result không được nhận.

## Status

`GET /api/agents/distributed/status`

công bố:

- CorrelationIdRequired=true;
- PermissionRecheckedOnClaim=true;
- PermissionRecheckedOnComplete=true;
- UntrustedNodesEligible=false;
- OfflineNodesEligible=false;
- CompanionTransportEnabled=true.

## API

Local/control plane:

- `GET /api/agents/distributed/status`
- `GET /api/agents/distributed/executions`
- `GET /api/agents/distributed/executions/{executionId}`
- `POST /api/agents/distributed/dispatch`

Authenticated node:

- `GET /api/companion/client/distributed/next`
- `POST /api/companion/client/distributed/{executionId}/complete`

Companion capability:

`distributed-agents`

## Persistence

Mỗi workspace:

`distributed-agent-{workspace}.json`

State corrupt thì service fail closed bằng DistributedAgentValidationException.

Execution state:

- queued;
- running;
- completed;
- failed;
- blocked.

## Audit

Actions:

- `agent.distributed.dispatch`
- `agent.distributed.claim`
- `agent.distributed.complete`

Audit luôn chứa correlation ID nhưng không chứa device token/private key.

## Safety

v2.8.5 không:

- dispatch offline node;
- dispatch untrusted node;
- dispatch capability chưa grant;
- coi permission snapshot là grant vĩnh viễn;
- accept complete sau khi permission bị revoke;
- accept wrong correlation ID;
- accept result từ device khác;
- tự tạo agent ngoài registry;
- bỏ workspace boundary;
- mở unauthenticated remote execution.

## Kiểm thử tự động

Workflow `distributed-agents-v285.yml` kiểm tra:

1. restore;
2. build;
3. dotnet test;
4. version 2.8.5;
5. correlationIdRequired=true;
6. permission re-check ở claim/complete;
7. secure-pair trusted Android node;
8. register + grant build;
9. dispatch thiếu confirmation bị chặn;
10. dispatch planner tạo queued execution;
11. permission snapshot=true;
12. claim trả cùng ExecutionId;
13. claim giữ nguyên CorrelationId;
14. revoke build permission;
15. complete cùng correlation nhưng permission đã revoke → HTTP 403;
16. execution thành blocked;
17. grant lại build;
18. dispatch developer execution mới;
19. claim giữ nguyên correlation;
20. wrong correlation complete → HTTP 403;
21. đúng correlation + permission còn hiệu lực → completed;
22. làm node stale/offline;
23. dispatch mới bị từ chối;
24. execution records được persist;
25. restart app;
26. completed execution vẫn giữ correlation + permission snapshot;
27. Companion công bố distributed-agents capability.
