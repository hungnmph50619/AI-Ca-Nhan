# v2.9.0 — Hệ thống quyền thống nhất

Mục tiêu của mốc này là gom các quyết định quyền rời rạc về một permission engine chung theo workspace.

## Mô hình quyền

Mỗi rule gồm:

- workspace;
- subject type;
- subject id;
- resource;
- action;
- effect `allow` hoặc `deny`;
- thời điểm tạo/cập nhật;
- thời điểm hết hạn tùy chọn.

Subject hỗ trợ:

- `user`
- `device`
- `companion`
- `agent`
- `system`

## Nguyên tắc

- Default deny.
- Explicit deny luôn thắng allow.
- Rule bị giới hạn theo workspace.
- Rule có thể hết hạn.
- Mọi thay đổi rule đều yêu cầu xác nhận.
- Permission state bị hỏng sẽ fail-closed.
- Có audit cho set/revoke.

## Device Capability integration

Device Capability v2.9.0 ghi grant/revoke vào Unified Permission System với dạng:

- subject: `device:{deviceId}`
- resource: `capability:{capability}`
- action: `use`

Khi kiểm tra access, Unified Permission rule là nguồn quyết định ưu tiên. Metadata cũ chỉ còn fallback tương thích cho dữ liệu từ phiên bản trước.

## API

- `GET /api/system/permissions/status`
- `GET /api/system/permissions`
- `POST /api/system/permissions`
- `POST /api/system/permissions/evaluate`
- `DELETE /api/system/permissions/{ruleId}`

## Safety boundary

v2.9.0 không:

- auto-grant quyền;
- coi thiếu rule là allow;
- cho allow vượt qua explicit deny;
- dùng rule workspace khác;
- bỏ qua expiry;
- sửa/xóa rule khi chưa xác nhận.
