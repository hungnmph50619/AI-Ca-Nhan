# v2.9.3 — Hoàn tác

Mục tiêu của mốc này là nâng Undo Foundation hiện có thành contract hoàn tác hệ thống rõ ràng, có thể truy vết từ tool invocation và fail-closed khi trạng thái đích đã thay đổi.

## Phạm vi hỗ trợ

v2.9.3 hỗ trợ hoàn tác các thay đổi filesystem trong workspace:

- xóa file vừa tạo;
- phục hồi file vừa ghi đè;
- phục hồi file vừa xóa;
- xóa thư mục vừa tạo;
- phục hồi thư mục rỗng vừa xóa;
- di chuyển file về vị trí cũ.

Không tuyên bố hỗ trợ rollback side effect ngoài filesystem.

## Safety contract

- bắt buộc xác nhận rõ ràng trước khi execute undo;
- workspace scoped;
- snapshot tối đa 512 KB;
- undo tồn tại tối đa 7 ngày;
- tối đa 500 bản ghi;
- SHA-256/precondition được revalidate ngay lúc rollback;
- nếu file đã thay đổi ngoài luồng, rollback bị chặn;
- snapshot bị xóa sau khi undo thành công;
- undo đã thực hiện không thể chạy lại.

## Invocation correlation

Mỗi undo record đã có `InvocationId`.

v2.9.3 dùng chính `InvocationId` làm system-log correlation ID cho:

- `tool.execute`;
- `undo.available`;
- `undo.execute`.

Nhờ đó có thể truy vết toàn bộ timeline tool → undo bằng system log/action explanation.

## API

API cũ tiếp tục giữ nguyên:

- `GET /api/undo`
- `GET /api/undo/{undoId}/assessment`
- `POST /api/undo/{undoId}/execute`

API bổ sung:

- `GET /api/undo/status`
- `GET /api/undo/invocations/{invocationId}`

## Status contract

Status công khai các giới hạn và boundary:

- `ExplicitConfirmationRequired=true`
- `PreconditionRevalidationRequired=true`
- `WorkspaceScoped=true`
- `InvocationCorrelationEnabled=true`
- `AuditTrailEnabled=true`
- `FileMutationsSupported=true`
- `NonFileSideEffectsSupported=false`
