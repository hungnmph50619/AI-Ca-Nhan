# v2.9.4 — Giới hạn tài nguyên

Mục tiêu của mốc này là hợp nhất resource guard của hệ thống thành contract có enforcement và observability rõ ràng.

## API request limits

v2.9.4 tiếp tục và củng cố các giới hạn:

- tối đa 600 API request/phút cho mỗi remote/workspace window;
- tối đa 16 API request đồng thời;
- tối đa 12 MB cho mỗi API request body;
- tối đa 2.048 rate-window được giữ trong bộ nhớ.

## Thay đổi chính

### Body-size enforcement

Ngoài kiểm tra `Content-Length`, middleware đặt `IHttpMaxRequestBodySizeFeature.MaxRequestBodySize` trước khi endpoint đọc body.

Điều này đóng đường bypass bằng request body không khai báo Content-Length khi server hỗ trợ body-size feature.

### Rate-window memory bound

Rate limiter trước đây cleanup khi dictionary lớn nhưng không có hard cap.

v2.9.4:

- cleanup window cũ trước khi tạo entry mới khi đã chạm ngưỡng;
- nếu sau cleanup vẫn đủ 2.048 entry thì fail-closed với 429;
- không cho dictionary rate-window tăng vô hạn.

### Resource counters

Hệ thống theo dõi từ lúc process khởi động:

- request API đã được nhận;
- request bị chặn vì payload;
- request bị chặn vì rate;
- request bị chặn vì concurrency;
- request bị chặn vì rate-window capacity;
- số request đang active;
- peak concurrent request;
- số rate-window hiện được giữ.

## API

- `GET /api/system/resources/status`

Status cũng công khai:

- maximum request rate;
- maximum concurrency;
- maximum request bytes;
- maximum tracked rate windows;
- backup count/source-size limits;
- enforcement flags;
- fail-closed contract.

## Safety boundary

v2.9.4 không tự tăng limit theo tải.

Khi guard bị vượt:

- payload quá lớn: HTTP 413;
- rate/window capacity: HTTP 429 + Retry-After;
- concurrency quá cao: HTTP 503 + Retry-After.
