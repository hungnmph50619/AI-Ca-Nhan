# v2.9.5 — Chống AI chạy vòng lặp

Mục tiêu của mốc này là chặn các vòng lặp tự động trước khi chúng tiêu tốn tài nguyên hoặc tạo side effect lặp vô hạn.

## Shared Loop Guard

Loop guard dùng chung hỗ trợ các scope:

- agent;
- tool;
- ci;
- delegation;
- retry;
- task;
- branch;
- automation;
- development.

Mỗi check được xác định bởi:

- workspace;
- scope;
- run ID;
- fingerprint;
- cost units.

## Giới hạn

- cùng fingerprint tối đa 3 lần trong cửa sổ 60 phút;
- tối đa 50 transitions cho một run;
- tối đa 100 cost units cho một run;
- tối đa 256 run được theo dõi;
- tối đa 2.048 fingerprint đang được theo dõi.

Khi vượt giới hạn, hệ thống fail-closed.

## Stop reason và audit

Mọi block ghi event:

- action: `loop-guard.blocked`;
- result: `blocked`;
- level: `security`;
- source: `loop-guard`;
- correlation ID: run ID;
- reason chứa loại guard và stop reason.

Nhờ vậy v2.9.2 Action Explanation có thể truy ngược lý do dừng.

## Integration thật

### Automation

Khi automation bị dependency block và định reschedule, fingerprint gồm task, current step và lý do block.

Nếu cùng trạng thái lặp quá ngưỡng:

- automation bị disable;
- state chuyển sang `interrupted`;
- không schedule vòng tiếp theo;
- stop reason được lưu vào LastMessage và audit.

### Roadmap Autopilot

Mỗi vòng verify thất bại tạo fingerprint từ:

- restore result;
- build result;
- test result;
- các failure summary.

Nếu cùng failure quay lại quá ngưỡng:

- không gọi AI repair thêm;
- checkpoint chuyển `loop-blocked`;
- run result trả `loop-blocked`;
- stop reason được audit.

Hard maximum repair attempts hiện có vẫn giữ nguyên như lớp bảo vệ thứ hai.

## API

- `GET /api/system/loop-guard/status`
- `POST /api/system/loop-guard/check?confirmed=true`
- `DELETE /api/system/loop-guard/{scope}/{runId}?confirmed=true`

Diagnostic mutation bắt buộc explicit confirmation.

## Safety boundary

Loop guard không tự resume run đã bị chặn. Người dùng hoặc workflow được kiểm soát phải review/reset state trước khi thử lại.
