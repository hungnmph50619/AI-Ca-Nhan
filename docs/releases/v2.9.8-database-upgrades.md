# v2.9.8 — Hệ thống nâng cấp database

Mục tiêu của mốc này là thay các nâng cấp schema ad-hoc bằng migration history có version/checksum, chạy tuần tự và fail-closed.

## Migration engine

Mỗi SQLite database được quản lý sẽ có bảng:

- `personalai_schema_migrations`

Mỗi record lưu:

- migration ID;
- checksum;
- mô tả;
- thời điểm áp dụng.

Khi khởi động:

1. Đọc migration history.
2. So checksum của migration đã ghi với code hiện tại.
3. Nếu checksum lệch: dừng nâng cấp và fail-closed.
4. Migration chưa có sẽ chạy tuần tự.
5. Mỗi migration chạy trong transaction SQLite.
6. Chỉ ghi history sau khi migration thành công.
7. Migration lỗi sẽ rollback.

## Component đã chuyển sang versioned migrations

### Audit database

- `audit-001-baseline`
- `audit-002-system-log`

Migration system-log thêm:

- `level`
- `source`
- `correlation_id`
- backfill dữ liệu cũ;
- index cho level/source/correlation.

### Undo database

- `undo-001-baseline`

Schema hiện tại và indexes được quản lý bằng cùng migration engine.

## Startup gate

`DatabaseUpgradeHostedService` ép Audit và Undo nâng schema khi app khởi động.

Nếu migration không đạt trạng thái up-to-date, startup bị chặn thay vì để background services chạy với schema không xác định.

## API

- `GET /api/system/database-upgrades/status`

Status công khai:

- startup migration enabled;
- checksum validation enabled;
- atomic migration enabled;
- fail-closed;
- số component;
- expected/applied migrations;
- migration IDs đã áp dụng theo component.

## Tương thích DB cũ

Migration được viết idempotent:

- database cũ chưa có migration history vẫn nâng cấp được;
- cột đã tồn tại không bị add lại;
- dữ liệu audit cũ được backfill;
- restart không chạy lại migration đã ghi.
