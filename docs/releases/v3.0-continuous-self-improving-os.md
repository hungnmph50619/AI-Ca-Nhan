# v3.0 — Hệ điều hành AI cá nhân tự cải tiến liên tục

Phiên bản release: **3.0.0**.

v3.0 khép roadmap bằng cách nâng Personal AI OS từ manifest nền v2.x thành một control plane thống nhất cho continuous self-improvement dưới các lớp permission, audit, policy, rollback, resource/loop guard, disaster recovery và emergency stop.

## Continuous self-improvement readiness

`GET /api/os/status` và `GET /api/os/manifest` bổ sung:

`continuousImprovement`

Readiness chỉ khả dụng khi đồng thời đạt:

- Autonomous Development controller sẵn sàng;
- policy bypass bị cấm;
- direct main push bị cấm;
- high-risk auto-merge bị cấm;
- Nightly Improvement giữ low-risk-only + downstream policy gates;
- Unified Permissions default-deny;
- System Log/Audit sẵn sàng;
- Undo có confirmation + precondition revalidation;
- Resource Limits fail-closed;
- Loop Guard fail-closed;
- Emergency Stop contract sẵn sàng và không đang engaged;
- Disaster Recovery integrity/path/rollback gates sẵn sàng;
- Database Upgrade up-to-date + checksum + atomic migration + fail-closed.

## Không tự bật vô điều kiện

v3.0 công bố:

- `Available`: safety plane có đủ để chạy continuous improvement có kiểm soát;
- `EnabledByDefault=false`: availability không đồng nghĩa tự bật;
- `NightlySchedulerEnabled`: phản ánh cấu hình runtime thực tế.

Nightly scheduler tiếp tục mặc định tắt trừ khi cấu hình explicit.

External AI/GitHub side effects vẫn cần confirmation, credential và policy gate tương ứng.

## Personal AI OS stage

OS contract:

- release version: `3.0.0`;
- stage: `v3.0`;
- next stage: `continuous-stable`;
- capability mới: `continuous-improvement`;
- governance layer chứa continuous improvement.

General autonomous agent loop và parallel tool calls không được tự mở bởi v3.0.

## Acceptance baseline

Runtime không tự suy diễn trạng thái GitHub Actions.

Field:

`AcceptanceBaseline = "v2.9.9/full-autonomous-development-test-v299.yml"`

chỉ ra benchmark release đã dùng để kiểm tra full autonomous development.

v2.9.9 acceptance đã kiểm tra controlled low-risk path:

detect/analysis
→ coding
→ testing
→ independent review
→ security
→ benchmark
→ push evidence
→ CI
→ merge-policy
→ local-sync
→ completed

với `PolicyBypassed=false`.

## Emergency-stop readiness invalidation

Khi system emergency stop được engage:

- execution surfaces mới bị khóa;
- `continuousImprovement.available` chuyển false;
- OS readiness có blocker;
- audit vẫn được giữ.

Sau explicit release và khi các safety gates khác vẫn healthy, readiness có thể trở lại true.

## Safety boundaries còn giữ nguyên

v3.0 không có nghĩa:

- AI có quyền tự cấp permission;
- AI được push thẳng main/master;
- high-risk change được auto-merge;
- external AI/GitHub side effect tự chạy không xác nhận;
- emergency stop có thể bị bypass;
- DB migration lỗi vẫn cho app chạy;
- corrupt backup được restore;
- retry/agent loop được chạy vô hạn;
- user decision bị thay thế bởi Decision Engine.

v3.0 là **continuous self-improvement có kiểm soát**, không phải autonomous execution không giới hạn.
