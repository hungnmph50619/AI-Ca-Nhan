# v3.0 Production Completion / E2E Hardening

Roadmap v2.5.3 → v3.0 đã hoàn thành ở mức kiến trúc và acceptance theo từng milestone. Giai đoạn này không tạo v3.1; mục tiêu là đóng các khoảng trống production còn được v3.0 công bố là Foundation/Controlled.

## Nguyên tắc

- Không làm yếu permission, confirmation, audit, undo, resource/loop guard hoặc emergency stop.
- Không cho push trực tiếp main/master.
- Không auto-merge thay đổi rủi ro cao.
- Thay đổi API cũ phải tương thích; API mới chỉ được bổ sung khi cần.
- Mọi capability chỉ được coi là hoàn tất khi có implementation, acceptance test và trạng thái runtime trung thực.

## Production readiness API

`GET /api/os/production-readiness`

Trả về:

- `complete`: đã đóng toàn bộ khoảng trống production hay chưa;
- `requiredCapabilities`: các capability cần hoàn thiện;
- `completeCapabilityCount`: số capability đã đạt mức Ready/Controlled theo OS manifest;
- `blockers`: khoảng trống hành vi còn lại.

## Baseline hiện tại

Các blocker được ghi rõ để hệ thống không tự đánh đồng `osContractReady=true` với “mọi chức năng production đã hoàn tất”:

1. Email: chưa có Gmail/Outlook OAuth, mailbox model và send/reply action chuyên dụng.
2. Calendar: chưa có provider-specific sync và create/update/delete event.
3. Browser: chưa có interactive login/form-submit/browser side effects có confirmation.
4. Android: chưa cho remote tool execution/task mutation qua unified permission gate.
5. Agent Framework: chưa có automatic delegation/tool execution qua bounded permission gate.
6. GitHub production E2E: acceptance side-effect hiện dùng fake GitHub API; chưa có sandbox-repository E2E thật.

## Definition of done

Production Completion chỉ đạt khi:

- `/api/os/production-readiness` trả `complete=true`;
- build + tests đạt;
- Personal AI OS v3.0 acceptance đạt;
- general CI đạt;
- từng blocker có acceptance test riêng;
- GitHub production E2E chạy trên sandbox repository thật, không dùng main/master và không dùng production credential ngoài scope test.
